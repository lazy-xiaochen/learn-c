## 工具链实测记录（2026-11-24）

运行 ASan 程序需要 `toolchain/.../bin` 在 PATH 中（`libclang_rt.asan_dynamic-x86_64.dll`），或把该 DLL 复制到 exe 旁边。

判题用编译参数（暂定）：
```
clang -std=c17 -Wall -Wextra -g -O0 -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=all
ASAN_OPTIONS=detect_stack_use_after_return=1
```

| 场景 | -O0 结果 | -O1 结果 |
|---|---|---|
| 堆越界写 | heap-buffer-overflow ✅ | ✅ |
| 释放后使用 | heap-use-after-free ✅ | ✅ |
| 重复释放 | attempting double-free ✅ | **未检测**（被优化掉） |
| 空指针解引用 | UBSan load of null pointer ✅ | ✅ |
| 返回局部变量地址 | stack-use-after-return ✅ | **未检测** |
| 有符号整数溢出 | UBSan signed integer overflow ✅ | ✅ |
| 无限深递归 | stack-overflow ✅ | ✅ |

结论：
- 判题检测必须用 **-O0**；
- `-fno-sanitize-recover=all` 必须加，否则 UBSan 报告后程序继续运行、退出码为 0；
- 单次编译约 230ms，远低于 10s 上限；
- 上表 -O0/-O1 差异本身可作为阶段 5「能跑不等于正确」的教学素材。

## 判题沙箱（阶段 0 产物）

文件：
- `native/runner.c` → `runner.exe`：Job Object 沙箱。限制 CPU 时间（20ms 轮询）、墙钟时间、进程内存、进程数 = 1、输出 64KB。
- `native/clearn_track.{h,c}`：编译时 `-include` 注入，跟踪 malloc/free，用于泄漏检测和 256MB 堆上限。
- `server/judge/`：`judge.js`（编译、运行、判题）、`security.js`（头文件白名单、危险函数黑名单）、`diagnostics.js`（编译报错中文解释）、`sanitizer.js`（ASan/UBSan 报告解析）、`static-rules.js`（静态隐患扫描）、`compare.js`（输出比对）、`exit-codes.js`。
- `tests/judge/run-judge-tests.mjs`：`npm run test:judge`，21 项端到端测试。

判题状态：AC / WA / TLE / MLE / RE / CE / UB，外加 **LEAK**（只用于要求检查泄漏的手写数据结构题）。
需求原文的状态集合里没有 LEAK，这是为"判题器检查内存泄漏"新增的状态。输出超过 64KB 按 WA 处理并注明原因。

实测中发现并解决的问题：
1. Job Object 自带的 CPU 时间限制（PerProcessUserTimeLimit）在嵌套 Job 下不触发 → 改为主动轮询。
2. ASan 影子内存让 256MB 的 Job 限制下用户只能拿到 192MB → Job 硬上限设为 512MB，MLE 以堆跟踪统计的 256MB 为准。
   **限制**：全局/栈上的超大数组不计入堆跟踪，只受 512MB 硬上限约束。
3. 沙箱禁止创建子进程，ASan 无法调用 llvm-symbolizer → 沙箱内 `symbolize=0`，程序结束后在沙箱外离线符号化（需处理 RVA + ImageBase）。
4. `ASAN_OPTIONS` 以冒号分隔，Windows 路径中的 `C:` 会破坏解析；而且栈溢出时 ASan 写不出 log 文件 → 报告统一走 stderr。
5. Windows 上 `abort()` 退出码是 3，与堆超限冲突 → 堆超限改用专用退出码 0x4D4C45。
6. 学习者程序使用最小环境变量（不继承用户环境），报告中去除临时目录路径（含用户名）。
7. 链接参数 `-Wl,--stack,67108864`：栈改为 64MB（Windows 默认只有 1MB）。
