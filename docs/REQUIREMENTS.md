## 一、角色与使命

你是全栈开发 Agent，负责从零构建一个面向零基础学习者的 C 语言学习平台。平台的终极验收标准是：一个完成全部学习路径的学习者，具备参加 C 语言相关岗位（嵌入式开发、系统开发、后端开发）技术面试的 C 语言能力。

"内容完整"的含义是：每一个知识点条目必须包含可运行的代码示例、明确的编译/运行说明、至少一个常见错误场景，并至少关联一道可在线判题的编程题或客观题。禁止出现只有标题或一句话概括的知识点占位。

## 二、知识体系：必须覆盖的全部模块

按以下七个阶段组织内容，每个阶段内的每一个子条目都是一个独立的内容单元，拥有完整的讲解、代码、题目和进度追踪。

### 阶段 1：C 语言基础语法与程序结构

覆盖：开发环境与编译流程（预处理→编译→汇编→链接）、第一个 C 程序的完整解剖（main 的签名、返回值、#include 的两种形式及搜索路径差异）、基本数据类型（char/short/int/long/float/double 的大小与表示范围，sizeof 运算符）、变量与常量（const、#define、字面量后缀）、运算符（算术、关系、逻辑、位运算、赋值、逗号、sizeof、优先级与结合性）、格式化输入输出（printf/scanf 的格式说明符、返回值、常见缓冲区问题）、控制流（if/else、switch 的 fall-through、for/while/do-while、break/continue/goto）、函数基础（声明与定义、值传递、作用域与生命周期、递归的栈展开）。

每个运算符优先级陷阱必须配可运行的演示代码，例如 a & b == c 的实际求值顺序、i = i++ 的未定义行为等。

### 阶段 2：数组、字符串与指针——C 语言的"分水岭"

这是 C 语言学习中淘汰率最高的部分，必须用最多的内容密度覆盖。

数组：一维/二维数组的内存布局、数组名退化为指针的精确时机、sizeof(arr) 在函数内外差异的底层原因、变长数组（VLA）的限制。

字符串：C 字符串的本质（以 '\0' 结尾的字节序列）、char[] 与 char * 在存储和可变性上的根本区别、strlen/strcpy/strcat/strcmp 的安全版本与非安全版本、字符串字面量的存储位置与修改后果、常见陷阱（sizeof("hello") 与 strlen("hello") 的区别，char *s = "abc"; s[0]='x' 的未定义行为）。

指针：指针的声明与解引用、指针算术（类型大小对步长的影响）、const 与指针的三种组合（const int *p / int * const p / const int * const p）的精确语义、多级指针、函数指针与回调、void * 的转换规则、野指针与悬垂指针、指针与数组的"等价"与"不等价"场景（&arr 与 arr 的类型差异，arr 在 sizeof 和 & 下的行为）。

此阶段必须包含"内存图"式讲解：每个指针/数组知识点用地址—内容对照图展示栈上变量的布局，避免纯文字描述。

### 阶段 3：函数、递归与程序结构

函数的调用约定（参数压栈顺序、返回值传递方式、cdecl 与 stdcall 的差异）、递归的执行栈与栈帧布局、尾递归的优化条件、static 函数与 static 局部变量的作用域和存储期、extern 与多文件编译、头文件卫士（#ifndef/#define/#endif）、链接属性（内部链接与外部链接）、inline 的语义。

递归部分必须包含：用调试器或打印语句展示每一层栈帧的 n 值和返回地址，让学习者"看见"递归。

### 阶段 4：结构体、联合体、枚举与内存对齐

struct 的定义、初始化、嵌套、指针成员与自引用（链表节点的定义基础）、typedef 的正确用法与陷阱、union 的内存共享语义与类型双关（type punning）的合法/未定义边界、enum 的本质是 int、内存对齐规则（offsetof 宏的使用，#pragma pack 的效果）、位域的内存布局与不可移植性、结构体作为函数参数的值传递代价与指针传递。

必须包含：用 sizeof 和 offsetof 验证不同对齐设置下结构体大小的实验代码，并解释为什么"调整成员顺序可以减小结构体大小"。

### 阶段 5：动态内存管理与未定义行为

malloc/calloc/realloc/free 的正确用法与返回值检查、内存泄漏的检测思路、悬垂指针的产生与避免、free 后重复释放、realloc 失败时的安全模式、栈与堆的本质区别（分配速度、生命周期、大小限制、碎片问题）。

未定义行为（UB）是此阶段的核心考核点，必须单独成节，覆盖：数组越界读写、有符号整数溢出、空指针解引用、未初始化变量读取、i = i++、printf 格式说明符与参数类型不匹配、memcpy 重叠区域、字符串字面量修改、函数返回局部变量的地址。每个 UB 条目配一段"故意写错"的代码和在不同编译选项（-O0 vs -O2）下的行为差异说明，强调"能跑不等于正确"。

### 阶段 6：文件 I/O 与预处理器

fopen/fclose/fread/fwrite/fprintf/fscanf/fgets/fputs 的用法与返回值语义、文本模式与二进制模式的差异（尤其在换行处理上）、文件定位（fseek/ftell/rewind）、标准流（stdin/stdout/stderr）的重定向。

预处理器：宏定义（对象宏与函数宏）、宏展开的陷阱（缺少括号导致的优先级错误、多次求值副作用）、# 和 ## 运算符、条件编译（#if/#ifdef/#ifndef/#elif/#else/#endif）、#include 的尖括号与双引号搜索策略、预定义宏（__FILE__/__LINE__/__DATE__/__func__）。

### 阶段 7：数据结构基础（C 语言实现）+ 就业冲刺

用 C 语言手工实现（不允许调用第三方容器库）：单向链表/双向链表的增删查改与反转、栈（数组实现与链表实现）、队列（循环数组与链表）、哈希表（链地址法）、二叉搜索树的基本操作、快速排序与归并排序、二分查找。每个数据结构必须包含内存布局图和常见 bug 清单（如链表删除节点后未释放、循环队列的 front/rear 条件判断）。

就业冲刺模块：整理 C 语言面试高频题（内存布局、static/extern/volatile/const 的作用、指针与数组的区别、结构体对齐、malloc 与 free 的配对、编译链接过程），提供口述级的标准答案和手写代码级的标准答案两种形式。

## 三、题库设计规范

### 3.1 难度分级（对标洛谷，但适配 C 语言学习场景）

| 难度 | 名称 | 颜色标识 | 知识边界 |
|---|---|---|---|
| L1 | 入门 | 红 | 基本 I/O、变量、顺序/分支/循环、一维数组遍历、简单字符串处理。题意直接，解法步骤 ≤ 3 步 |
| L2 | 基础 | 橙 | 函数封装、二维数组、指针基础（交换/遍历）、字符串库函数使用、简单递归。需要正确处理边界但算法不复杂 |
| L3 | 进阶 | 黄 | 指针与数组混合、结构体、动态内存分配、文件读写、链表基础操作。需要设计数据结构或处理指针关系 |
| L4 | 核心 | 绿 | 链表/栈/队列完整实现、递归回溯、简单哈希、排序算法实现。需要处理内存管理和边界条件的组合 |
| L5 | 面试级 | 蓝 | 未定义行为辨析、内存布局推理、位运算技巧、多文件链接、手写数据结构 + 完整错误处理。对标 C 语言岗位技术面难度 |

难度评定依据"所需知识 + 实现复杂度 + 陷阱密度"，不依据代码行数。

### 3.2 每道编程题必须包含的结构（缺一不可）

```
题目ID: 唯一标识
标题: 一句话描述任务
难度: L1–L5
关联知识点: [知识点ID列表]
题目描述: 完整、无歧义的叙述，包含输入格式、输出格式、数据范围
示例: 至少 2 组输入/输出示例，其中 1 组覆盖边界
测试用例:
  - 可见用例: 与示例对应，供学习者自测
  - 隐藏用例: 至少 5 组，必须覆盖：
      · 正常边界（最小/最大输入规模）
      · 退化情况（空输入、单个元素、全相同值）
      · C 语言特有陷阱（缓冲区溢出风险、整数溢出范围、空指针路径、
        未初始化变量触发点、`scanf` 返回值未检查的后果）
提示: 分层提示（第1层方向性，第2层具体知识点，第3层接近解法但不给代码）
参考代码: 完整、可编译、带注释的 C 代码，使用 `gcc -Wall -Wextra -std=c17` 无警告
复杂度说明: 时间/空间复杂度，以及优化方向
常见错误: 列出 ≥ 3 种学习者可能提交的错误写法及其后果（如 WA/TLE/UB）
```

禁止只做"选择题型"的题目。编程题占比不低于 60%，客观题只用于快速检验概念（如指针 const 语义、运算符优先级、UB 判断），且客观题的每个选项都要有解析。

### 3.3 C 语言特有题目的强制要求

以下类型的题目每个阶段至少 2 道：
- 指针关系推理题：给出 int a[5]; int *p = a; 及一系列操作，判断哪些表达式合法、值是什么、是否有 UB。
- 内存布局题：给出 struct 定义，求 sizeof、各成员 offsetof，并解释对齐决策。
- UB 辨析题：给出多段短代码，判断哪些包含未定义行为，并说明在 -O0 和 -O2 下可能的不同表现。
- 手写数据结构题：给出一组接口声明，要求实现完整功能，判题器检查功能正确性 + 内存泄漏（用 AddressSanitizer 检测）。
- 编译/链接错误诊断题：给出多个源文件，判断声明/定义/链接问题，或解释某个链接错误的原因。

## 四、平台功能与交互设计

### 4.1 核心闭环：学 → 练 → 评 → 激励

**学**：知识点页面采用"左文右码 + 底部题目入口"布局。每个知识点页面必须有"可交互代码块"——学习者可以直接在页内编辑代码并点击"运行"，看到输出，无需跳转。代码块下方显示"常见坑"折叠面板和"关联题目"卡片。

**练**：内置 CodeMirror 或 Monaco Editor，支持 C 语法高亮、基础自动补全（关键字和标准库函数名）、Tab 缩进、行号、错误行标记。提交后显示判题状态（AC / WA / TLE / MLE / RE / CE / UB），CE 时展示完整的编译器输出，RE 时如果触发了 AddressSanitizer，展示 sanitizer 报告摘要。

**评**：每次提交后，除了判题结果，给出结构化反馈：通过了哪些用例、失败了哪些用例（隐藏用例只显示"第 N 组失败"和输入规模类别，不直接泄露完整输入）、本次代码中检测到的潜在问题（如未检查 malloc 返回值、scanf 返回值未使用、存在未初始化变量等，基于静态规则扫描）。反馈语言面向初学者，避免纯编译器术语堆砌。

**激励**：经验值（XP）体系——完成知识点 +10，通过 L1 题 +20，L2 +40，L3 +70，L4 +120，L5 +200；首次 AC 额外 +50%。连续学习天数（streak）、阶段完成徽章、L5 题目"面试级通过"标识。不做排行榜（避免初学者挫败感），改为"个人进度可视化"：用热力图或进度环展示各阶段完成比例。

### 4.2 进度追踪

每个知识点有状态：未开始 / 学习中 / 已掌握（通过关联题目 ≥ 1 道 AC 且完成客观题）。每个阶段有"阶段完成度"环形图。首页仪表盘展示：当前 streak、总 XP、已 AC 题目按难度分布、下一步推荐（基于未掌握知识点中难度最低的）。

## 五、UI / UX 设计规范

### 5.1 视觉方向

风格定位：暗色优先的"专注工作台"。参考 StackBlitz 的暗色体系与 smolcoder 的"quiet workbench"思路：深色中性背景（#151619 / #1c1f25 层级），正文纯白或近白（#ffffff / #e4e5e9），强调色使用高对比青色（#00aeda 附近）用于链接、按钮、进度高亮，辅助色使用琥珀色（#f5a623 附近）标识 L5/面试级内容，绿色（#3fb950）标识 AC/通过，红色（#f85149）标识 WA/错误，黄色（#d29922）标识 TLE/警告。

必须支持亮色/暗色切换，亮色模式背景 #fcfcfc，表面 #ffffff，阴影用 1px 细边框代替重投影。切换状态持久化到 localStorage。

字体：代码区使用等宽字体栈（'JetBrains Mono', 'Fira Code', 'Cascadia Code', monospace），正文使用系统无衬线字体栈。代码区字号不小于 14px，行高 1.6。

### 5.2 关键页面布局

**知识点页面**：桌面端采用 360px 侧栏 + 自适应主内容。侧栏是可折叠的阶段/知识点树，当前知识点高亮，已完成项显示勾选，有题目的知识点显示题目数徽标。主内容顶部是知识点标题 + 掌握状态标签，正文是讲解 Markdown + 可交互代码块，右侧（宽屏时）或底部（窄屏时）是关联题目卡片列表。

**做题页面**：三栏布局（桌面端）：左栏题目描述（可折叠），中栏代码编辑器（主体），右栏判题结果面板（提交后从底部滑出或从右侧展开）。题目描述区顶部固定显示难度徽标、通过率、关联知识点标签。代码编辑器顶部工具栏包含语言（固定 C）、运行/提交按钮、重置代码、查看提示。提交按钮在请求期间禁用并显示 loading 状态，防止重复提交。

**仪表盘**：顶部一行四个统计卡片（streak、总 XP、已 AC、当前阶段完成度），下方左侧是难度分布条形图（用颜色区分 L1–L5），右侧是"下一步推荐"列表，每项可点击直达。

### 5.3 响应式与可访问性

≥ 1024px 三栏/两栏布局；768–1023px 两栏，题目描述折叠为抽屉；< 768px 单栏，编辑器占满宽度，判题结果以底部 sheet 形式弹出。所有可交互元素有 :focus-visible 轮廓。代码编辑器支持键盘操作（Ctrl+Enter 运行，Ctrl+Shift+Enter 提交，Tab 缩进）。暗色模式下对比度满足 WCAG AA。

## 六、技术约束与架构建议

**前端**：Vue 3 + Vite 或 React + Vite。代码编辑器使用 CodeMirror 6（轻量、对 C 语言支持良好）或 Monaco Editor。状态管理使用 Pinia/Zustand。禁止使用任何 UI 组件库来"堆砌"界面——组件库可以用于基础表单控件（按钮、对话框、下拉），但知识点页面、做题页面、仪表盘的核心布局必须手写，以保证视觉一致性和设计意图的落地。

**后端**：Node.js（Express/Fastify）或 Python（Flask/FastAPI）均可。判题服务必须与 Web 服务进程隔离：提交的 C 代码在独立进程中编译运行（Docker 容器或至少独立子进程 + 资源限制）。强制安全措施：编译超时 ≤ 10s，运行超时 ≤ 3s，内存限制 ≤ 256MB，输出截断 ≤ 64KB，危险函数/头文件黑名单（system、fork、exec、popen、<windows.h> 等）在提交时静态拒绝或在沙箱中阻断。判题使用 GCC，编译参数建议 -std=c17 -Wall -Wextra -fsanitize=address,undefined（对于 RE 检测），但不能仅依赖 sanitizer 判定 AC——必须以实际输出与预期输出比对为准。

**数据**：知识点内容以 Markdown/JSON 结构化存储，题目以 JSON/YAML 存储（遵循第三节的结构），测试用例与题目元数据分离存储。判题记录持久化，用于进度计算和反馈。

## 七、Agent 的工作流程与交付要求

按以下顺序执行，每一步完成后产出可验证的中间产物：

**第 1 步：知识体系结构化。** 输出一个完整的 JSON 或 YAML 文件，包含全部 7 个阶段、每个阶段下的所有知识点条目（到"变量与常量"这一级粒度），每个条目包含：id、title、stage、prerequisites（依赖的知识点 ID 列表）、associated_problem_ids（暂时可空，第 2 步填充）。此步完成后先输出知识点总数和各阶段分布，确认覆盖度。

**第 2 步：题库生成。** 基于第 1 步的知识点列表，为每个知识点生成至少 1 道编程题 + 1 道客观题（L1 阶段可适当增加客观题比例以降低挫败感）。每道题严格遵循第 3.2 节的结构。此步完成后输出题库统计（总题数、各难度分布、各阶段分布），并抽取 3 道不同难度的题目完整展示，确认质量。

**第 3 步：平台实现。** 按第 4–6 节的要求实现前端 + 后端 + 判题服务。优先保证做题闭环（知识点页面 → 代码编辑器 → 提交 → 判题结果 → 进度更新）的端到端可用，再打磨 UI 细节和仪表盘。

**第 4 步：内容填充与自检。** 将第 1、2 步的内容接入平台。自检清单：每个知识点页面都有可运行代码示例且运行输出正确；每道题的参考代码在平台判题器中能 AC；每道题的隐藏用例至少包含 1 组会触发 C 语言特有陷阱的用例；暗色/亮色切换正常；移动端布局不横向滚动；提交按钮防重复提交生效。
