## 讲解

### 递归不是"跳回自己"，而是"再建一层帧"
初学者常把递归想象成"函数又从头跑了一遍"。更准确的画面是：**同一个函数的多份栈帧同时存在**。每一层都有自己的 `n`、自己的局部变量、自己的返回地址；它们互不覆盖，只是按后进先出的顺序创建和销毁。

所以"看见递归"这件事，本质上就是看见一串帧。而帧是看不见的——C 语言没有提供遍历栈的语法。可行的办法只有两种：

1. **打印每层的参数**：`n` 是每层最直接的"身份证"；
2. **打印每层的位置**：深度、帧编号、返回地址——但返回地址的**数值**不可靠，只能看相对关系。

这一页把两种办法都走一遍，重点讲清楚"为什么要这么打印、哪些能依赖、哪些不能"。

### 用缩进把"层"画出来
最实用的可视化技巧是缩进：每进入一层就多缩进两个空格。这样输出本身就是一棵倒着的树：

```c run id=rv-trace
#include <stdio.h>

static void walk(int n, int depth) {
    printf("%*s进入 n=%d\n", depth * 2, "", n);
    if (n > 1) {
        walk(n / 2, depth + 1);
        walk(n - n / 2, depth + 1);
    }
    printf("%*s离开 n=%d\n", depth * 2, "", n);
}

int main(void) {
    walk(5, 0);
    return 0;
}
```
```output
进入 n=5
  进入 n=2
    进入 n=1
    离开 n=1
    进入 n=1
    离开 n=1
  离开 n=2
  进入 n=3
    进入 n=1
    离开 n=1
    进入 n=2
      进入 n=1
      离开 n=1
      进入 n=1
      离开 n=1
    离开 n=2
  离开 n=3
离开 n=5
```

`%*s` 里的 `*` 表示"宽度由前一个参数给出"：`depth * 2` 是多少，就打印多少个空格。这种写法比手写循环干净，也不会引入额外的局部变量。

读这棵"树"要注意两件事：

- **两行 `进入 n=2` 和它下面的内容都在缩进 1 的位置**，说明它们是同一层的两个子调用（`5 / 2 = 2` 和 `5 - 5 / 2 = 3`）。注意 `walk(5)` 的两个孩子是 2 和 3，不是 2 和 2——`n - n / 2` 是"另一半"，不是 `n / 2`；
- **每一层都打印两次**（进入、离开），所以总行数是帧数的两倍。`离开` 的顺序正好是 `进入` 的逆序，这就是"递推"与"回归"两个阶段。

### 给每一帧一个编号：进入顺序和返回顺序不是一回事
`n` 会重复（很多层的 `n` 都是 1），光看 `n` 分不清是哪一帧。加一个"帧编号"就清楚了：进入时从全局计数器领一个号，这个号在这一帧的整个生命周期里不变。

```c run id=rv-frame-id
#include <stdio.h>

static int next_id;

static long long walk(int n, int depth) {
    int id = ++next_id;                        /* 本帧的编号：进入的顺序 */
    printf("%*s帧 #%d：n=%d\n", depth * 2, "", id, n);
    long long total = n;
    if (n > 1) {
        total += walk(n / 2, depth + 1);
        total += walk(n - n / 2, depth + 1);
    }
    printf("%*s帧 #%d 返回：n=%d total=%lld\n", depth * 2, "", id, n, total);
    return total;
}

int main(void) {
    long long total = walk(5, 0);
    printf("总帧数 %d，根返回值 %lld\n", next_id, total);
    return 0;
}
```
```output
帧 #1：n=5
  帧 #2：n=2
    帧 #3：n=1
    帧 #3 返回：n=1 total=1
    帧 #4：n=1
    帧 #4 返回：n=1 total=1
  帧 #2 返回：n=2 total=4
  帧 #5：n=3
    帧 #6：n=1
    帧 #6 返回：n=1 total=1
    帧 #7：n=2
      帧 #8：n=1
      帧 #8 返回：n=1 total=1
      帧 #9：n=1
      帧 #9 返回：n=1 total=1
    帧 #7 返回：n=2 total=4
  帧 #5 返回：n=3 total=8
帧 #1 返回：n=5 total=17
总帧数 9，根返回值 17
```

两个顺序值得对照着看：

- **编号是"进入顺序"**：`#1`、`#2`、`#3`…… 一个帧一旦建立，编号就固定，直到它返回都不变；
- **`total` 是"返回顺序"算出来的**：叶子帧先算出 `1`，父层才能把子层的结果加进来。`帧 #2` 的 `total` 要等 `#3`、`#4` 都返回之后才等于 `2 + 1 + 1 = 4`。

`total` 的计算顺序是理解递归返回值的关键：**返回值的计算发生在回归阶段，而不是递推阶段**。`帧 #2` 在打印"进入"的那一刻，`total` 还只是 `2`；等两个孩子都回来，它才变成 4。

### 返回地址：每层都返回到"同一个地方"
教材里常见的做法是每层打印 `__builtin_return_address(0)`。它确实能拿到"返回地址"——但对递归来说，这个信息的信息量比想象中小得多：**所有递归层都返回到同一条指令**（也就是递归调用点之后的那条），因为递归调用在源码里只有一个调用点。

```c run id=rv-retaddr
#include <stdio.h>

static void *rec_callsite;               /* 递归调用点的返回地址：只记录一次 */
static int seen;

static void probe(int n) {
    void *ra = __builtin_return_address(0);
    if (n < 3 && !seen) {
        rec_callsite = ra;               /* 第一次递归调用返回后要回到的指令 */
        seen = 1;
    }
    printf("n=%d：%s\n", n,
           n < 3 ? (ra == rec_callsite ? "返回到同一个递归调用点" : "返回到别的调用点")
                 : "这一层是 main 调进来的");
    if (n > 0) {
        probe(n - 1);
    }
}

int main(void) {
    probe(3);
    return 0;
}
```
```output
n=3：这一层是 main 调进来的
n=2：返回到同一个递归调用点
n=1：返回到同一个递归调用点
n=0：返回到同一个递归调用点
```

结论：**用返回地址区分递归的层是行不通的**。真正区分层的是"参数 + 栈上的位置 + 帧编号"，返回地址只说明"返回到哪条指令"。`n=3` 那一层不同，是因为它是被 `main` 里另一个调用点调进来的——返回地址对应的是**调用点**，不是**层**。

### 为什么不能把地址打印出来当输出
上面的程序只比较返回地址是否相等，**从不打印它的数值**。这不是偷懒，而是硬性要求：

- **ASLR**：操作系统每次运行都会随机化代码段和栈的加载地址，同一个程序两次运行，打印出来的地址就不一样；
- **ASan 插桩**：本平台默认开启 AddressSanitizer，它会在每个局部变量周围插红区、用"假栈"（fake stack）管理帧，局部变量的地址甚至可能不在真栈上；
- **优化级别**：`-O0` 和 `-O2` 的栈布局完全不同，`-O2` 下很多变量根本不在内存里；
- **编译器/库版本**：换个版本，帧大小和排列都会变。

所以本平台的所有演示都遵守一条规则：**要么打印相对关系（相同/不同、第几层、偏移量），要么只讲原理**。凡是"输出依赖地址数值"的代码，都不能用来判题，也不能写进笔记当结论。

### 帧的数量决定了输出规模
理解了"一层一帧"，就能估算递归的代价。对 `walk(n)` 这种"每个大于 1 的 n 分裂成两个子调用"的递归，帧数满足：

```
F(1) = 1
F(n) = 1 + F(n/2) + F(n - n/2)      (n > 1)
```

因为每次分裂都把 n 大致减半，帧数接近 `2n - 1`。打印两行的话，输出规模就是 `4n - 2` 行：

```c run id=rv-frame-count
#include <stdio.h>

static int frames(int n) {
    if (n <= 1) {
        return 1;
    }
    return 1 + frames(n / 2) + frames(n - n / 2);
}

int main(void) {
    for (int n = 1; n <= 8; n++) {
        int f = frames(n);
        printf("n=%d：帧数 %d，打印行数 %d\n", n, f, 2 * f);
    }
    return 0;
}
```
```output
n=1：帧数 1，打印行数 2
n=2：帧数 3，打印行数 6
n=3：帧数 5，打印行数 10
n=4：帧数 7，打印行数 14
n=5：帧数 9，打印行数 18
n=6：帧数 11，打印行数 22
n=7：帧数 13，打印行数 26
n=8：帧数 15，打印行数 30
```

帧数正好是 `2n - 1`。这个规律很重要：它说明"看得见的递归"规模是可控的（线性），而真正可怕的是**每层分裂成多个子调用**的递归（比如斐波那契的朴素递归是指数级），那时帧数会爆炸——不过这属于第 4 个知识点"递归的典型模式"。

### 一个帧在多深的地方？用"深度"而不是地址
如果想知道"当前这层在栈的什么位置"，正确做法是记录**深度**（根为 0，每递归一层加 1），而不是读地址。深度是逻辑量，稳定、可比较、可打印；地址是物理量，随环境变化。上一节的缩进就是深度的直接应用。

```memory title="walk(5) 递归到最深处的三层帧（只画参数与返回地址的归属，地址为示意）"
帧序号 | 参数 n | 返回地址指向 | 说明
第 1 层 | 5 | main 里调用之后的那条指令 | 根帧，深度 0，缩进 0
第 2 层 | 2 | walk 内部的递归调用点 | 深度 1，n 是本层自己的 2
第 3 层 | 1 | walk 内部的递归调用点 | 深度 2，叶子：n=1 不再递归
```

三层帧同时存在，参数各不相同，却共享同一个返回地址（后两行）。这就是"看见递归"的完整画面：**帧靠参数区分，靠深度定位，靠返回地址回到上一层的执行点**。

### 递归深度和栈溢出
每多一层就多一帧，帧里装着参数、局部变量、返回地址、保存的寄存器。栈的容量有限，所以递归深度也有上限。本页的 `walk(5)` 只用了 9 帧，随便跑；但如果递归是"每次只减 1"的线性递归，深度就等于 n，n 到几十万时栈就会被撑爆（本平台判 `RE`，报 `AddressSanitizer: stack-overflow`）。

判断方法很简单：**先估深度，再估每层帧大小**。分治递归的深度是 log₂n（40 亿也就 32 层），安全；线性递归的深度是 n，必须警惕。真正的解法是把递归改成迭代（自己用数组维护栈），或者改成尾递归让编译器优化——那是后面两个知识点的事。

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra trace.c -o trace
./trace
```

```bash
clang -std=c17 -Wall -Wextra trace.c -o trace
./trace
```

本平台使用 Clang（x86-64 Windows）。和"看栈帧"相关的几个开关：

- `-O0`：不优化，帧结构最接近源码，适合观察；`-O2` 下递归可能被改成循环（尾递归）或内联，帧就看不到了；
- `-fno-omit-frame-pointer`：保留帧指针链，调试器（gdb/lldb）靠它回溯调用栈；
- `-fsanitize=address`：本平台默认。它会改变帧布局，还会把"函数返回后仍在使用栈上变量"抓成 `stack-use-after-return`；
- `-g`：带上调试信息，`gdb` 里可以用 `bt` 一次看到整条调用栈——这是"看见递归"最专业的工具：

```bash
gcc -std=c17 -g -O0 trace.c -o trace
gdb ./trace
# (gdb) break walk
# (gdb) run
# (gdb) bt          ← 每次断住都能看到当前是第几层、每层的 n 是多少
```

`bt` 的输出形如：

```text
#0  walk (n=1, depth=2) at trace.c:5
#1  walk (n=2, depth=1) at trace.c:8
#2  walk (n=5, depth=0) at trace.c:8
#3  main () at trace.c:16
```

这就是"每层参数"的权威答案：帧号 `#0` 是当前层，`#1`、`#2` 是还活着的上层。自己打印时用缩进和帧编号，本质上是在模拟 `bt`。

## 常见错误

### 把"当前层参数"存进一个全局变量 [WA]
全局变量只有一份。递归的每一层都往里写，最后留下来的是**最后写进去的那个值**，回到上层时读到的早就不是自己的参数了：

```c run id=rv-err-global
#include <stdio.h>

static int last;                        /* 只有一份：被所有层共用 */

static void walk(int n) {
    last = n;
    if (n > 1) {
        walk(n / 2);
        walk(n - n / 2);
    }
    printf("n=%d，last=%d\n", n, last);
}

int main(void) {
    walk(3);
    return 0;
}
```
```output
n=1，last=1
n=1，last=1
n=1，last=1
n=2，last=1
n=3，last=1
```

`n=2` 和 `n=3` 这两层本来想读"自己的 n"，结果读到的都是子调用留下的 1。正确做法是把参数作为**局部变量**或**函数参数**保存（每层一份），或者用一个数组按深度存（`stack[depth] = n`）。

### 以为递归只有一个方向，忘了回归阶段也有输出 [WA]
"进入时打印"只看到递推；"离开时打印"才看到回归。很多同学写递归打印时只写一半，于是输出看起来像"一路往下"，误以为函数执行完就结束了。记住：**每个 `if` 之后的代码，都在所有子调用返回之后执行**，`printf` 放在递归调用之后，输出的就是逆序。

### 打印真实地址，还指望输出稳定 [WA]
`printf("%p", &x)` 的输出每次运行都可能不同（ASLR），开了 ASan 之后更是和真栈毫无关系。把它写进程序逻辑（比较大小、算偏移、当哈希）必然出错；写进题目的预期输出更是没法判题。要观察就用"深度、帧编号、相同/不同"这类相对量。

### 递归深度过大导致栈溢出 [RE]
线性递归 100 万层，每层几十到上百字节，总用量就能到几十 MB，超过栈上限。本平台报 `AddressSanitizer: stack-overflow` 并判 `RE`。写递归前先估深度：分治的 log n 安全，线性的 n 要小心，n 可能到 10⁵ 以上时直接用迭代。

### 用全局变量做缩进，却忘了在返回时恢复 [WA]
缩进量必须跟着"当前深度"走：进入时加、离开时减。只加不减，兄弟节点就会越缩越深，整棵树歪掉。正确写法是把 `depth` 作为参数传递（本页所有例子都这么做），或者在递归调用后手动 `depth--`。

## 客观题

### q-s3-recursion-visual-1 single
下面的递归函数执行 `f(2)`，输出是什么？

```c
void f(int n) {
    if (n == 0) {
        printf("0");
        return;
    }
    printf("%d", n);
    f(n - 1);
    printf("%d", n);
}
```

- [x] `21012`
  > 正确。`f(2)` 先打印 `2`，进入 `f(1)` 打印 `1`，进入 `f(0)` 打印 `0` 并返回；回到 `f(1)` 执行递归调用之后的 `printf`，打印 `1`；再回到 `f(2)`，打印 `2`。所以是 `2 1 0 1 2`。注意 `f(0)` 走的是 `return` 分支，不会执行后面的打印，所以中间的 `0` 只出现一次。
- [ ] `210`
  > 错。这是"只看到递推阶段"的结果——漏掉了递归调用之后的两次打印。`f(1)` 和 `f(2)` 在子调用返回后各还有一条 `printf`，它们的输出是回归阶段产生的。
- [ ] `01210`
  > 错。这是把"最深层先打印"当成了顺序。实际上 `printf("%d", n)` 写在递归调用**之前**，所以最外层的 `2` 最先输出，`0` 在中间。
- [ ] `21210`
  > 错。这个序列把 `f(1)` 的两次打印记成了 `2` 和 `1`。每一层打印的都是**自己**的 `n`：`f(2)` 打印两个 `2`（一前一后），`f(1)` 打印两个 `1`，`f(0)` 只打印一个 `0`。
