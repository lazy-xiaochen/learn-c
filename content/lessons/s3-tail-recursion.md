## 讲解

### 两个版本的阶乘
同一个阶乘，可以写成"算完再乘"的普通递归，也可以写成"边算边乘"的尾递归：

```c run id=fact-tail
#include <stdio.h>

static long long fact_rec(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fact_rec(n - 1);          /* 不是尾调用：拿到结果后还要乘 n */
}

static long long fact_tail(int n, long long acc) {
    if (n <= 1) {
        return acc;
    }
    return fact_tail(n - 1, acc * n);    /* 尾调用：返回后什么都不用做 */
}

int main(void) {
    printf("%lld\n", fact_rec(10));
    printf("%lld\n", fact_tail(10, 1));
    return 0;
}
```
```output
3628800
3628800
```

两者答案一样，但执行方式有一个本质区别：`fact_rec` 在递归调用**返回之后**还要做一次乘法，所以调用者的栈帧必须一直留着；`fact_tail` 在递归调用返回之后**无事可做**，直接把结果还给上一层。

### 什么是尾调用
**尾调用**（tail call）指的是：一个函数的最后一次动作，是"调用另一个函数，并把它返回的值原样作为自己的返回值"。判断标准只有一条——**调用的结果是不是直接成了本函数的返回值，调用之后还有没有别的事要做**：

| 写法 | 是尾调用吗 | 原因 |
|---|---|---|
| `return f(x);` | 是 | 返回值就是 `f(x)`，调用后无事可做 |
| `return n * f(x);` | 否 | 返回后还要做乘法 |
| `return f(x) + 1;` | 否 | 返回后还要加 1 |
| `f(x); return 0;` | 否 | 返回值不是 `f(x)`，调用后还有 `return 0;` |
| `if (...) return f(x); ...` | 是 | 只要这一条路径上 `return f(x)` 之后没有别的事 |

这里的 `f` 可以是别的函数（**尾调用**），也可以是函数自己（**尾递归**，tail recursion）。尾递归是尾调用的特例。

### 为什么尾调用能省栈
普通递归的每一层都在"等"下一层的结果：

- `fact_rec(3)` 调用 `fact_rec(2)`，然后**停在那里**，等结果回来再乘 3；
- 所以 `fact_rec(3)` 的栈帧（保存着 `n = 3`）必须保留，一直到 `fact_rec(2)` 返回为止。

尾递归不需要等：

- `fact_tail(3, 1)` 先把"还欠的那次乘法"算进参数里（`acc * n = 3`），再去调用 `fact_tail(2, 3)`；
- 当前这一层的 `n` 和 `acc` 以后再也用不到了，栈帧可以**原地复用**：把参数改成 `(2, 3)`，然后跳回函数开头。

于是普通递归的栈深度是 n，尾递归（被优化后）的栈深度是 1：

```memory title="fact(3) 与 fact_tail(3, 1) 的栈对比（地址为示意，实际每次运行可能不同；-O0 下不做尾调用优化）"
地址     | 内容            | 变量      | 场景             | 说明
0x0fe0   | n = 3           | n         | fact_rec(3)      | 返回后要算 3 * 结果，帧必须保留
0x0fd0   | n = 2           | n         | fact_rec(2)      | 返回后要算 2 * 结果
0x0fc0   | n = 1           | n         | fact_rec(1)      | 返回后要算 1 * 结果
0x0fb0   | n = 0           | n         | fact_rec(0)      | 终止条件，返回 1；此刻栈上有 4 个帧
0x0fe0   | n = 3, acc = 1  | n, acc    | fact_tail(3, 1)  | 尾调用：算出 acc*n = 3 就可以扔掉这一层
0x0fe0   | n = 2, acc = 3  | n, acc    | fact_tail(2, 3)  | 复用同一个帧，地址不变
0x0fe0   | n = 1, acc = 6  | n, acc    | fact_tail(1, 6)  | 终止条件，返回 acc = 6；始终只有 1 个帧
```

注意最后三行的地址**完全相同**：那不是一个"新的栈帧"，而是同一块内存在被反复改写。这就是"省栈"的字面含义。

### 把普通递归改写成尾递归：加一个累加器
改写的手法叫**累加器**（accumulator）：把"返回之后要做的计算"提前做掉，结果塞进参数里传下去。阶乘的 `acc * n`、求和的 `acc + n`、斐波那契的两个累加器都是这个套路：

```c run id=fib-gcd-tail
#include <stdio.h>

/* 斐波那契：把 f(n-1) 和 f(n-2) 两个"待办"都挪进参数 */
static long long fib_tail(int n, long long a, long long b) {
    if (n == 0) {
        return a;
    }
    return fib_tail(n - 1, b, a + b);    /* 尾调用 */
}

/* 辗转相除本身就是尾递归：除完直接返回，没有后续计算 */
static int gcd_tail(int a, int b) {
    if (b == 0) {
        return a;
    }
    return gcd_tail(b, a % b);           /* 尾调用 */
}

int main(void) {
    printf("%lld\n", fib_tail(10, 0, 1));
    printf("%d\n", gcd_tail(1071, 462));
    return 0;
}
```
```output
55
21
```

改写的要点：

1. 想清楚"返回后原本要做什么"——那次乘法、加法、取最大值；
2. 把它变成参数：`f(n-1, acc * n)`，让下一层带着"已经算好的部分"继续；
3. 累加器的**初始值**要对：阶乘是 1，求和是 0，斐波那契是两个种子 0 和 1。

第 3 点看着简单，实际上最容易错：`fact_tail(5, 0)` 会老老实实返回 0，因为任何数乘 0 都是 0。这个错误在下面的常见错误里还会出现。

### C 标准不保证尾调用优化
这是本课最重要的一句话：**"尾调用"只是"允许被优化"的写法，C 标准从来没有要求编译器必须优化它。**

标准对栈帧、对递归深度没有任何承诺。编译器可以选择把尾调用变成跳转（于是栈深度 O(1)），也可以选择老老实实压栈（于是栈深度 O(n)）。同一份源码，换个优化级别就可能换一种行为。下面用实验验证——这是一段标准的尾递归求和，深度 100 万：

```c run id=tail-deep-O0 expect=RE stdin="1000000\n"
#include <stdio.h>

static long long sum_tail(long long n, long long acc) {
    if (n == 0) {
        return acc;
    }
    return sum_tail(n - 1, acc + n);
}

int main(void) {
    long long n;
    if (scanf("%lld", &n) != 1) {
        return 0;
    }
    printf("%lld\n", sum_tail(n, 0));
    return 0;
}
```

`-O0` 下没有任何优化：100 万层调用，每层一个栈帧，64MB 栈很快被用完，程序崩溃，本平台判 `RE`。现在**一个字都不改**，只把编译选项换成 `-O2`：

```c run id=tail-deep-O2 opt=-O2 stdin="1000000\n"
#include <stdio.h>

static long long sum_tail(long long n, long long acc) {
    if (n == 0) {
        return acc;
    }
    return sum_tail(n - 1, acc + n);
}

int main(void) {
    long long n;
    if (scanf("%lld", &n) != 1) {
        return 0;
    }
    printf("%lld\n", sum_tail(n, 0));
    return 0;
}
```
```output
500000500000
```

同一个函数、同一份源码，`-O0` 崩、`-O2` 正常。原因就是 `-O2` 下 Clang 把尾调用改成了跳转（sibling call），栈始终只有一层。这也顺带给出两个结论：

- **不要用"我用的是尾递归"来论证程序不会爆栈**——你得说清"在什么编译器、什么优化级别下"；
- **本平台判题默认 `-O0`**，所以题目里深度上百万的递归必须改写成循环，尾递归救不了你。

还有一点要澄清：`-O2` 下 Clang 不止会优化尾调用，它有时还能把 `return n + f(n-1)` 这种"返回后要加一下"的**线性递归**也改写成循环（相当于自动加了累加器）。但这些都是具体编译器的实现细节，换个编译器、换个版本就可能没有。**能依赖的只有标准，而标准什么都没保证。**

### 哪些递归改不成尾递归
尾调用要求"调用之后无事可做"，所以下面这些天然不满足：

- **后序遍历**：必须先递归处理左右子树，再处理自己（`f(left); f(right); 处理自己;`）——两次调用后面都还有事；
- **归并排序**：递归排好两半之后还要合并，返回后要用到两个子结果；
- **分治求值**：`return max(left, right, cross)` 这种必须拿到两个子结果再合并。

这类问题要改成迭代，只能自己用数组模拟栈。这也是为什么"递归转迭代"没有万能公式：**尾递归能自动转，非尾递归得手动搬栈。**

### 什么时候用尾递归，什么时候用循环
| 场景 | 建议 |
|---|---|
| 深度可能上万（链表遍历、累加、状态机） | 直接写循环，别赌优化 |
| 深度只有几十层、逻辑天然递归 | 普通递归更易读，不必强求尾递归 |
| 需要"递归写法的简洁 + 不爆栈" | 在**明确开启优化**的构建里用尾递归，并在注释里写清依赖 |
| 编译期就要保证不爆栈 | 只能写循环；C 没有可移植的 `musttail` |

一句话：**尾递归是一种"编译器可能帮你把递归变成循环"的写法，不是语言保证的特性。** 学习它的价值在于理解调用栈和优化边界，而不是把它当成省栈的银弹。

### 小结：三个层次
1. **写法层**：`return f(...)` 是尾调用，`return n * f(...)` 不是；
2. **机制层**：尾调用时当前帧没有待办事项，理论上可以复用；
3. **工程层**：能不能复用取决于编译器和优化级别，C 标准不管，所以深度大的递归请写循环。

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra -O0 rec.c -o rec      # 不优化：观察栈溢出
gcc -std=c17 -Wall -Wextra -O2 rec.c -o rec      # 开优化：观察尾调用被消除
./rec
```

本平台使用 Clang，命令等价：

```bash
clang -std=c17 -Wall -Wextra -O0 rec.c -o rec
clang -std=c17 -Wall -Wextra -O2 rec.c -o rec
```

几个和尾调用有关的开关：

- `-O0`：默认不优化，尾递归照样每层压栈；
- `-O1` / `-O2`：Clang 和 GCC 通常在这里打开 sibling call 优化（`-foptimize-sibling-calls`）；
- `-fno-optimize-sibling-calls`：显式关掉尾调用优化，用来验证"你的程序是不是真的依赖了它"；
- `-fsanitize=address`：栈溢出会报 `ERROR: AddressSanitizer: stack-overflow`，本平台判 `RE`。

验证方法：把同一个可执行文件分别用 `-O0` 和 `-O2` 编译，喂一个很大的 n，看前者崩溃、后者正常。如果两者都正常，说明你的递归深度还不够，或者编译器在低优化级别也做了别的优化。

## 常见错误

### 累加器初值给成 0，结果永远是 0 [WA]
`fact_tail(5, 0)` 返回 0：乘法链上只要有一个 0，后面全是 0。阶乘的累加器初值是 **1**，求和是 **0**，斐波那契是两个种子 **0 和 1**。写尾递归时先把"空状态"想清楚。
```c run id=fact-tail-zero-acc
#include <stdio.h>

static long long fact_tail(int n, long long acc) {
    if (n <= 1) {
        return acc;
    }
    return fact_tail(n - 1, acc * n);
}

int main(void) {
    printf("%lld\n", fact_tail(5, 0));   /* 错：初值应该是 1 */
    return 0;
}
```
```output
0
```

### 以为写了尾递归就不会爆栈 [RE]
在 `-O0` 下（也就是本平台判题的默认设置），尾递归和普通递归一样每层压栈。深度 100 万的尾递归求和会直接 `RE`。如果题目要求处理 `n = 10⁶` 这种规模，请老老实实写 `for` 循环：
```c
long long sum_to(long long n) {
    long long s = 0;
    for (long long i = 1; i <= n; i++) {
        s += i;
    }
    return s;
}
```

### 把"返回后还要做事"的调用当成尾调用 [WA]
`return n * f(n - 1);`、`return f(n - 1) + 1;`、`f(n - 1); return 0;` 都不是尾调用。判断方法：**把这次调用删掉，看这一层的返回值还能不能算出来**。算不出来（还要用它的结果做运算），就不是尾调用。

### 尾递归改写时把参数顺序弄反 [WA]
`fib_tail(n - 1, b, a + b)` 里两个累加器的顺序是有含义的（`a` 是 f(k)，`b` 是 f(k+1)），写成 `fib_tail(n - 1, a + b, b)` 会算出另一串数。改写完先手算 n = 0、1、2、3 四个小值核对。

### 依赖优化，却没在构建脚本里写清优化级别 [WA]
代码在本地 `-O2` 下跑得好好的，换到 `-O0` 的调试构建就崩——因为尾调用优化没了。凡是"靠深度递归 + 指望优化"的实现，都要在注释和构建配置里写清楚前提；更稳妥的做法是直接用循环。

## 客观题

### q-s3-tail-recursion-1 single
下面四个写法中，哪一个才是**尾调用**（tail call）？

- [x] `return f(n - 1);`
  > 正确。调用的返回值直接成为本函数的返回值，调用之后没有任何后续计算，当前栈帧可以立即被复用。
- [ ] `return n * f(n - 1);`
  > 不是。拿到 `f(n - 1)` 的结果之后还要乘 `n`，本层的栈帧必须保留到乘法完成，所以这是普通递归。
- [ ] `return f(n - 1) + 1;`
  > 不是。返回后还要加 1，调用之后仍有待办事项，不满足尾调用的条件。
- [ ] `f(n - 1); return 0;`
  > 不是。调用的结果被丢弃，本函数返回的是常量 0，这次调用不构成"返回值就是调用结果"的尾调用。（某些编译器仍可能把它优化成跳转，但那是另一回事。）
