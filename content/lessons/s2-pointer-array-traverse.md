## 讲解

### `a[i]` 从头到尾就是 `*(a + i)`
C 标准对下标运算的定义只有一句话：`a[i]` 等价于 `*(a + i)`。不是"很像"，是**完全等价**——编译器在内部就是把前者翻译成后者。

既然是加法，交换两个加数不影响结果，于是 `*(a + i)` 也等于 `*(i + a)`，再按定义翻译回来就是 `i[a]`。所以下面四个表达式都能取出同一个元素：

```c run id=subscript-is-deref
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("a[2]   = %d\n", a[2]);
    printf("*(a+2) = %d\n", *(a + 2));
    printf("*(2+a) = %d\n", *(2 + a));
    printf("2[a]   = %d\n", 2[a]);      /* 合法，但请不要在正式代码里这么写 */
    return 0;
}
```
```output
a[2]   = 30
*(a+2) = 30
*(2+a) = 30
2[a]   = 30
```

`2[a]` 能编译、能运行，是因为它只是 `*(2 + a)` 的另一种拼法。**它合法不代表它可读**：工程代码里永远写 `a[i]`，只在面试题或"看懂别人在干什么"时才需要认识 `i[a]`。

理解这条等价关系以后，"指针能不能当数组用"就不再神秘了：只要 `p` 指向某块连续内存的首元素，`p[i]` 就是 `*(p + i)`，和数组下标一模一样。

### 用指针遍历数组
既然 `a[i]` 就是 `*(a + i)`，遍历数组至少有两种等价写法：用下标，或者让指针自己往后走。第二个循环里每次 `p++` 让 `p` 前进 `sizeof(int)` 个字节（指针算术由类型决定步长），`p < a + n` 是标准的"走到末尾就停"的写法。

```c run id=two-ways
#include <stdio.h>

int main(void) {
    int a[6] = {2, 4, 6, 8, 10, 12};
    int n = 6;

    printf("下标：");
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");

    printf("指针：");
    for (int *p = a; p < a + n; p++) {
        printf("%d ", *p);
    }
    printf("\n");

    int *q = a + 3;                   /* q 指向 a[3] */
    printf("q[0] = %d，q[1] = %d，*(q - 2) = %d\n", q[0], q[1], *(q - 2));
    return 0;
}
```
```output
下标：2 4 6 8 10 12 
指针：2 4 6 8 10 12 
q[0] = 8，q[1] = 10，*(q - 2) = 4
```

最后一行值得多看一眼：`q` 并不是数组名，它只是指向数组**中间**的 `a[3]`。但 `q[0]` 依然等于 `*(q + 0)`，也就是 `a[3]`；`q[1]` 是 `a[4]`；`*(q - 2)` 是 `a[1]`。**"指针 + 下标"这套规则对数组里的任意位置都成立**，不只是首元素。

也正因为如此，`q - a` 能算出 `q` 当前的下标（结果类型是 `ptrdiff_t`，用 `%td` 打印）。这比打印地址有用得多——地址每次运行都可能不同，而"下标"是稳定的。

### `*p++`、`(*p)++`、`*++p` 到底谁先谁后
遍历时最容易写混的就是这三个。记住两条规则就够了：

1. 后缀 `++` 的优先级高于 `*`，所以 `*p++` 是 `*(p++)`；前缀 `++` 与 `*` 同级且从右往左结合，所以 `*++p` 是 `*(++p)`；
2. 后缀 `++` 的语义是"先用旧值，再加一"；前缀是"先加一，再用新值"。

```c run id=increment-order
#include <stdio.h>

int main(void) {
    int a[4] = {1, 2, 3, 4};
    int *p = a;

    int x = *p++;                     /* 取 a[0] 的值，然后 p 指向 a[1] */
    printf("x = %d，*p = %d\n", x, *p);

    int y = (*p)++;                   /* 把 a[1] 加 1，p 本身不动 */
    printf("y = %d，a[1] = %d，*p = %d\n", y, a[1], *p);

    int z = *++p;                     /* 先把 p 指向 a[2]，再取值 */
    printf("z = %d，下标 = %td\n", z, p - a);
    return 0;
}
```
```output
x = 1，*p = 2
y = 2，a[1] = 3，*p = 3
z = 3，下标 = 2
```

对照着看：

- `*p++`：**取的是旧位置的值，指针前进一格**。适合"边走边取"，`while (n--) sum += *p++;` 就是这种用法；
- `(*p)++`：解引用之后对**元素**加一，指针不动。适合"把数组每个元素加一"；
- `*++p`：指针先前进一格，再取新位置的值。它和 `*(p + 1)` 的结果一样，但 `p` 自己也被改了。

初学时建议少用 `*p++` 这种"一句话两件事"的写法：拆成 `int v = *p; p++;` 虽然多一行，但不会看错。真要用，就必须清楚每一步之后 `p` 指向哪里。

### 首尾双指针：反转数组
指针遍历最典型的应用是"从两端往中间夹"。用两个指针 `l`、`r` 分别指向首元素和末尾元素，交换它们的值，然后 `l` 前进、`r` 后退，直到相遇：

```c run id=reverse-array
#include <stdio.h>

/* 反转 [first, last) 区间：last 指向"末尾元素的下一个位置" */
static void reverse(int *first, int *last) {
    while (first < last) {
        last--;
        int t = *first;
        *first = *last;
        *last = t;
        first++;
    }
}

int main(void) {
    int a[7] = {1, 2, 3, 4, 5, 6, 7};
    reverse(a, a + 7);
    for (int i = 0; i < 7; i++) {
        printf("%d%c", a[i], i + 1 == 7 ? '\n' : ' ');
    }
    return 0;
}
```
```output
7 6 5 4 3 2 1
```

几个细节：

- 这里用的是"左闭右开"约定 `[first, last)`：`last` 指向末尾元素的**下一个位置**，所以循环里先 `last--` 才拿到真正的末尾元素。`a + 7` 这个"末尾后一位"的指针是合法的，可以参与比较，但**不能解引用**。
- 交换必须借助临时变量 `t`。写成 `*first = *last; *last = *first;` 时，第一句已经把 `*first` 覆盖掉了，第二句再把同一个值写回去，两个位置就都变成了右边的值。
- 长度为奇数时中间那个元素会自己和自己交换一次（`first == last` 时那一轮实际上不做任何改变），这没有危害；长度为偶数时两个指针会正好错开，循环自然结束。

`reverse` 的参数是两个指针而不是"数组 + 长度"，这是 C 里表达"一段区间"的常见方式：调用者用 `a` 和 `a + n` 指定范围，函数内部只关心 `first`、`last` 两个边界。

### 内存图：数组是一段内存，指针只是"指向其中一格"
假设 `int a[5]` 从 `0x1000` 开始：

```memory title="int a[5]={10,20,30,40,50}; int *p = a; int *q = &a[3];（地址为示意，实际每次运行可能不同）"
地址     | 内容   | 变量 | 说明
0x1000   | 10     | a[0] | 
0x1004   | 20     | a[1] | 
0x1008   | 30     | a[2] | 
0x100c   | 40     | a[3] | 
0x1010   | 50     | a[4] | 
0x2000   | 0x1000 | p    | 执行 int *p = a; 之后
0x2000   | 0x1008 | p    | 执行 p += 2 之后：p 的内存没变，是里面的内容变了
0x2008   | 0x100c | q    | int *q = &a[3];
```

看这张图要抓住两点：

1. **数组本体是连续的 5 个格子**，`a` 只是这块内存的名字；
2. **指针是单独的一个变量**，它自己占 8 字节，内容是"某一格的地址"。`p++` 改的是 `p` 这个格子的内容，不是数组。

所以 `*p`、`p[0]`、`p[-2]` 都只是"用 p 的内容做一次加法，再解引用"，与数组下标没有任何本质区别。

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra traverse.c -o traverse
./traverse
```

本平台使用 Clang，命令等价：

```bash
clang -std=c17 -Wall -Wextra traverse.c -o traverse
./traverse
```

两个实用建议：

- 想确认指针当前指向哪个元素时，**打印 `p - a` 而不是地址**。地址受地址空间随机化（ASLR）影响，每次运行都可能不同；`p - a` 是稳定的下标，还能直接用眼睛核对。
- 一定要打印地址时用 `%p` 并强制转换成 `void *`：`printf("%p\n", (void *)p);`。用 `%d` 打印指针在 64 位平台上会把 8 字节截成 4 字节，属于未定义行为。

加上运行时检查，越界读会立刻暴露：

```bash
clang -std=c17 -Wall -Wextra -g -fsanitize=address,undefined traverse.c -o traverse
```

## 常见错误

### 循环条件写成 p <= a + n，多读一个元素 [RE]
`a + n` 是"末尾元素的下一个位置"，它本身可以比较，但**不能解引用**。写成 `p <= a + n`，最后一轮会读取 `a[n]`，那是数组之外的栈内存。本平台的 AddressSanitizer 会直接报告越界并判 `RE`。
```c run id=err-past-end expect=RE
#include <stdio.h>

int main(void) {
    int a[5] = {1, 2, 3, 4, 5};
    int s = 0;
    for (int *p = a; p <= a + 5; p++) {
        s += *p;                      /* p == a + 5 时越界 */
    }
    printf("%d\n", s);
    return 0;
}
```

### 交换写成 *l = *r; *r = *l;，两个位置都变成右边的值 [WA]
看起来像"交换"，其实第一步就把左边的旧值覆盖掉了。必须在覆盖之前用临时变量把左值存起来。下面的代码反转 `1 2 3 4 5` 得到的是 `5 4 3 4 5`：只有右半边的值被复制过来，左半边原来的数据丢了。
```c run id=err-broken-swap
#include <stdio.h>

int main(void) {
    int a[5] = {1, 2, 3, 4, 5};
    int *l = a;
    int *r = a + 4;

    while (l < r) {
        *l = *r;                      /* 错：a 的值在这里被覆盖 */
        *r = *l;                      /* 写回去的还是同一个值 */
        l++;
        r--;
    }

    for (int i = 0; i < 5; i++) {
        printf("%d%c", a[i], i + 1 == 5 ? '\n' : ' ');
    }
    return 0;
}
```
```output
5 4 3 4 5
```

### 第二次遍历前忘了把指针拨回开头 [RE]
指针遍历结束后，`p` 已经停在"末尾的后一位"，它不是数组名，不会自己回到开头。如果接着用同一个 `p` 再遍历一次，第一次 `*p` 就越界了。
```c run id=err-no-reset expect=RE
#include <stdio.h>

int main(void) {
    int a[5] = {1, 2, 3, 4, 5};
    int *p = a;
    long long s = 0;

    for (int i = 0; i < 5; i++) {
        s += *p;
        p++;                          /* 循环结束时 p == a + 5 */
    }
    for (int i = 0; i < 5; i++) {
        s += *p;                      /* 错：从 a + 5 开始，越界 */
        p++;
    }
    printf("%lld\n", s);
    return 0;
}
```

要么在第二轮之前写 `p = a;`，要么干脆让每个循环各自声明 `for (int *q = a; ...)`——后者的作用域只在这个循环里，不容易犯这种错。

### 以为 `p[i]` 只能用在数组名上 [WA]
`p[i]` 与 `*(p + i)` 完全等价，对任何合法指针都成立，包括指向数组中间甚至数组末尾前一位的指针。把"指针遍历"和"数组下标"当成两套互不相通的写法，会导致多余的临时变量、绕远路的代码，也容易在 `p[i]` 该不该从 0 开始这类问题上犯糊涂。

## 客观题

### q-s2-pointer-array-traverse-1 single
下面这段代码执行完之后，`x` 和 `*p` 分别是多少？

```c
int a[3] = {5, 6, 7};
int *p = a;
int x = *p++;
```

- [x] `x = 5`，`*p = 6`
  > 正确。后缀 `++` 优先级高于 `*`，所以 `*p++` 是 `*(p++)`：先取 `*p`（即 `a[0] = 5`）赋给 `x`，然后 `p` 自增指向 `a[1]`，因此 `*p` 变成 6。
- [ ] `x = 6`，`*p = 6`
  > 这是把 `*p++` 当成了 `*++p`。前缀 `++` 才是"先加再取值"；这里用的是后缀，取的是自增之前的值。
- [ ] `x = 5`，`*p = 5`
  > 这是把 `*p++` 当成了 `(*p)++`。那种写法修改的是 `a[0]` 的值（5 变成 6），`p` 本身不移动，所以 `*p` 会是 6 而不是 5；`x` 虽然也是 5，但整个行为完全不同。
- [ ] `x = 6`，`*p = 5`
  > 两个结论都和实际相反：既以为先自增，又以为指针没动。用规则核对一遍——后缀先取值、再自增。
