## 讲解

### 数组名代表"第一个元素的地址"
在内存里，数组是一块**连续的**存储空间。数组名 `a` 在表达式里通常会被转换成"第一个元素的地址"`&a[0]`，所以：

- `*a` 就等于 `a[0]`；
- `a + i` 指向第 i 个元素（下一节讲指针时细说）；
- 知道了首地址和下标，就能算出任何一个元素的地址。

```c run id=first
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("*a = %d\n", *a);
    printf("a[2] = %d，*(a + 2) = %d\n", a[2], *(a + 2));
    return 0;
}
```
```output
*a = 10
a[2] = 30，*(a + 2) = 30
```

`a[2]` 和 `*(a + 2)` 是同一个元素的两种写法，后面的指针内容会反复用到这条等价关系。

### 元素地址 = 首地址 + 下标 × 元素大小
每个 `int` 占 4 字节，元素又是一个挨一个放的，所以第 i 个元素的地址就是：

```
&a[i] = &a[0] + i * sizeof(int)
```

下面不打印具体地址（每次运行都可能不同），而是打印**每个元素相对首地址的字节偏移**，这样结果就是确定的：

```c run id=offset
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    for (int i = 0; i < 5; i++) {
        long off = (long)((char *)&a[i] - (char *)&a[0]);
        printf("a[%d] 相对首地址偏移 %ld 字节\n", i, off);
    }
    return 0;
}
```
```output
a[0] 相对首地址偏移 0 字节
a[1] 相对首地址偏移 4 字节
a[2] 相对首地址偏移 8 字节
a[3] 相对首地址偏移 12 字节
a[4] 相对首地址偏移 16 字节
```

偏移量每次正好增加 4——这就是"连续存放"的直接证据。如果把 `int` 换成 `double`（8 字节），偏移会每次增加 8。

```memory title="int a[5] = {10, 20, 30, 40, 50}; 首地址假设为 0x1000（示意图，实际值每次运行可能不同）"
地址     | 内容 | 变量   | 相对偏移
0x1000   | 10   | a[0]   | 0
0x1004   | 20   | a[1]   | 4
0x1008   | 30   | a[2]   | 8
0x100c   | 40   | a[3]   | 12
0x1010   | 50   | a[4]   | 16
```

### 整个数组占多少字节
`sizeof a` 是**整个数组**的字节数，等于"元素个数 × 每个元素的大小"。它和 `sizeof a[0]` 完全是两回事：

```c run id=size
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("整个数组 %zu 字节\n", sizeof a);
    printf("一个元素 %zu 字节\n", sizeof a[0]);
    printf("一共 %zu 个元素\n", sizeof a / sizeof a[0]);
    return 0;
}
```
```output
整个数组 20 字节
一个元素 4 字节
一共 5 个元素
```

### 连续存储的三个推论
1. **访问任意元素一样快**：算地址只需要一次乘法和一次加法，所以 `a[0]` 和 `a[999]` 的耗时相同（这叫随机访问）。
2. **越界会踩到相邻的内存**：`a[5]` 已经出了数组，它那块内存可能属于别的变量。写它可能悄悄改掉别的数据，也可能直接崩溃——这正是"数组越界是未定义行为"的原因。
3. **中间不能有空洞**：数组一旦定义，大小就固定了，不能在使用中"变长"（需要动态内存，第 5 阶段才学）。

## 常见错误

### 以为数组里存的是"地址"
`a` 是数组，`a[0]` 才是元素。打印 `a[0]` 得到的是值 10；打印 `a`（用 `%p`）得到的是首地址。初学者常把两者混为一谈。

### 把 `sizeof a` 当成元素个数
`sizeof a` 是**字节数**。要得到元素个数必须再除以 `sizeof a[0]`。反过来，把 `sizeof a` 当成"最后一个下标"则会越界。

### 用变量当下标却忘了检查范围
`a[k]` 里的 k 来自输入时，必须先确认 `0 <= k && k < 5`。直接 `scanf("%d", &k); printf("%d", a[k]);`，输入 100 就会读到数组外的内存，属于未定义行为。

### 认为越界只是"读到垃圾值"
读越界已经不可控，**写**越界更危险：它可能改掉旁边的变量、返回地址，甚至让程序在完全无关的地方崩溃，排查起来非常困难。

## 客观题

### q-s2-array-memory-1 single
`int a[10];` 的首地址是 `0x1000`，那么 `&a[4]` 是多少？（本平台是 64 位环境，`int` 占 4 字节）

- [x] `0x1010`
  > 正确。偏移 = 4 × 4 = 16 字节，0x1000 + 0x10 = 0x1010。
- [ ] `0x1004`
  > 0x1004 是 `&a[1]`：偏移 1 × 4 = 4 字节。
- [ ] `0x1014`
  > 0x1014 对应下标 5（偏移 20 字节），把"第 4 个元素"错数成了下标 5。
- [ ] `0x1040`
  > 这是把下标 4 当成了 4 个"10 进制位"，误算成 0x40。地址按字节算，不是按位或按十进制位。
