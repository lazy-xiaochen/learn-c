## 讲解

### 数组名在表达式里会"退化"成指向首元素的指针
`int a[5];` 里 `a` 的类型是 `int[5]`——一个**数组类型**，不是指针。但在大多数表达式里，数组名会被自动转换成"指向首元素的指针"（`int *`），这个转换叫**退化（decay）**：

```c
int a[5];
int *p = a;        /* a 退化成 &a[0] */
printf("%d", a[2]); /* 等价于 *(a + 2) */
```

退化有两个重要的例外：**`sizeof` 的操作数**和**`&` 的操作数**。在这两个位置，数组名保持"整个数组"的身份，而这正是所有困惑的来源。

### 值相同、类型不同的三个表达式
`a`、`&a[0]`、`&a` 打印出来的地址完全一样，但它们是**三种不同的类型**：

| 表达式 | 值 | 类型 | `+1` 前进 |
|---|---|---|---|
| `a`（退化成） | 首元素地址 | `int *` | 4 字节 |
| `&a[0]` | 首元素地址 | `int *` | 4 字节 |
| `&a` | 整个数组的地址（数值同上） | `int (*)[5]` | **20 字节** |
| `a + 0` | 首元素地址 | `int *` | 4 字节 |

```c run id=ap-same
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int (*q)[5] = &a;          /* q 的类型：指向“含 5 个 int 的数组”的指针 */

    printf("a 与 &a[0] 的值相同？%s\n", a == &a[0] ? "是" : "不是");
    printf("q 与 &a 的值相同？%s\n", q == &a ? "是" : "不是");
    printf("(*q)[2] = %d\n", (*q)[2]);   /* *q 就是整个数组，再取下标 */
    printf("sizeof *q = %zu\n", sizeof *q);
    return 0;
}
```
```output
a 与 &a[0] 的值相同？是
q 与 &a 的值相同？是
(*q)[2] = 30
sizeof *q = 20
```

注意 `a == &a[0]` 能编译（两边都是 `int *`），而 `a == &a` 不能——一边 `int *`、一边 `int (*)[5]`，类型不兼容。**值一样不代表类型一样**，这是本课最核心的一句话。

### `&a` 的类型为什么是 `int (*)[5]`
`&` 的作用是"取这个对象的地址"，得到的类型是"指向该对象类型的指针"。数组 `a` 的对象类型是 `int[5]`，所以：

```
&a 的类型 = 指向 int[5] 的指针 = int (*)[5]
```

读法：`q` 是一个指针，指向"含有 5 个 `int` 的数组"。因为 `q` 指向的是**一整个数组**，`q + 1` 自然要跳过一整个数组，也就是 5 × 4 = 20 字节：

```c run id=ap-step
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("a + 1 相对 a 前进 %ld 字节\n", (long)((char *)(a + 1) - (char *)a));
    printf("&a + 1 相对 &a 前进 %ld 字节\n", (long)((char *)(&a + 1) - (char *)&a));
    return 0;
}
```
```output
a + 1 相对 a 前进 4 字节
&a + 1 相对 &a 前进 20 字节
```

这里把两个指针都转成 `char *` 再相减，得到的是**字节数**；如果直接写 `(&a + 1) - &a`，单位是"数组"，结果是 1。同一个地址，两种类型，走一步的距离差了 5 倍——这就是"指针类型决定步长"的直接后果。

顺带说明：`&a + 1` 指向数组末尾的下一个位置，**构造**它是合法的（标准允许指向"末尾的下一个"），但**解引用**它是越界访问，属于未定义行为。

### `sizeof`：数组名"不退化"的场合
`sizeof` 想知道"这个对象占多少字节"，所以它必须看到对象的**完整类型**，数组名在这里不会退化：

```c run id=ap-sizeof
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    printf("sizeof a = %zu\n", sizeof a);
    printf("sizeof a[0] = %zu\n", sizeof a[0]);
    printf("sizeof &a = %zu\n", sizeof &a);
    printf("sizeof p = %zu\n", sizeof p);
    return 0;
}
```
```output
sizeof a = 20
sizeof a[0] = 4
sizeof &a = 8
sizeof p = 8
```

四行结果各有含义：

- `sizeof a = 20`：整个数组 5 × 4 = 20 字节。这是**唯一**能"从数组本身算出元素个数"的办法：`sizeof a / sizeof a[0]`。
- `sizeof a[0] = 4`：一个元素 4 字节。
- `sizeof &a = 8`：`&a` 是**指针**（`int (*)[5]`），指针就是 8 字节。它和 `sizeof *&a` 完全不同——后者是 20，因为 `*&a` 又变回了数组本身。
- `sizeof p = 8`：`p` 是指针变量，8 字节。**指针的大小和它指向什么完全无关**，`char *`、`double *`、`int (*)[5]` 全是 8 字节。

### 内存里：两条指针，同一个起点
把 `p`（`int *`）和 `q`（`int (*)[5]`）都指向 `a` 之后，它们存的地址一模一样，但"一步"的定义完全不同：

```memory title="int a[5] = {10,...,50}; int *p = a; int (*q)[5] = &a;（地址是示意值）"
地址     | 内容   | 变量 | 类型        | 一步前进
0x1000   | 10     | a[0] | int         | —
0x1004   | 20     | a[1] | int         | —
0x1008   | 30     | a[2] | int         | —
0x100c   | 40     | a[3] | int         | —
0x1010   | 50     | a[4] | int         | —
0x1014   | 越界   | a + 5 | int *      | 4 字节
0x2000   | 0x1000 | p    | int *       | 4 字节
0x2008   | 0x1000 | q    | int (*)[5]  | 20 字节
```

`p` 和 `q` 的内容都是 `0x1000`，所以解引用 `*p` 得到 10、`(*q)[0]` 也得到 10；但 `p + 1` 是 `0x1004`，`q + 1` 是 `0x1014`。**指针的"步长"完全由类型决定，而类型只存在于编译期**。

### 什么时候"等价"，什么时候"不等价"

**等价的场合**（数组名就是首元素地址）：

1. **下标访问**：`a[i]` 与 `*(a + i)` 完全等价，`p[i]` 也一样（`p[i]` 就是 `*(p + i)`）。
2. **作为函数实参**：`f(a)` 传的就是 `&a[0]`。函数参数写成 `int arr[]` 或 `int arr[5]`，编译器都当成 `int *` 处理。
3. **指针算术**：`a + i`、`p + i` 指向同一个元素，`a + i == p + i` 成立。

**不等价的场合**（数组名 ≠ 指针变量）：

1. **`sizeof`**：`sizeof a` 是 20，`sizeof p` 是 8。
2. **`&`**：`&a` 是 `int (*)[5]`，`&p` 是 `int **`，虽然值可能相同，类型和步长完全不同。
3. **赋值与自增**：数组名**不是可修改的左值**，`a = p;`、`a++`、`++a` 全部编译错误。数组名背后没有一块"存放指针的存储空间"，它就是编译器符号表里的一个地址。
4. **函数参数里**：`void f(int arr[5])` 里的 `arr` 是指针，`sizeof arr` 是 8 而不是 20——"数组长度"这个信息在传参时**丢失**了，所以必须额外传一个 `n`。
5. **字符串字面量初始化**：`char s[] = "abc";` 是在栈上复制一份可修改的副本；`char *p = "abc";` 只是指向只读区的字面量。这是后面字符串部分的内容，但根源就是"数组 vs 指针"。

一句话总结：**数组名在"值"的层面几乎总等于首元素地址，但在"类型、可赋值性、sizeof"这三个层面完全不等价**。凡是拿不准的时候，问自己一句："编译器在这里看到的是数组类型，还是退化后的指针类型？"

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra arrptr.c -o arrptr
./arrptr
```

本平台用 Clang，命令等价：`clang -std=c17 -Wall -Wextra arrptr.c -o arrptr`。

几个实用提醒：

- **`sizeof` 的结果是 `size_t`**，用 `%zu` 打印；用 `%d` 在 64 位平台上可能出错。
- **Clang/GCC 会对"用 sizeof 计算指针所指数组大小"给出警告**，例如 `sizeof(a + 0)`、函数参数上的 `sizeof arr`。这些警告正是在提醒你"这里已经退化成指针了"，不要忽略。
- **`-Wpedantic`** 可以抓出更多"看起来能编、其实依赖扩展"的写法。
- 想确认类型，可以故意写错让编译器告诉你：`int (*q)[5] = &a;` 编译通过，把它改成 `int *q = &a;` 就会得到 `incompatible pointer types` 错误——**编译器报的类型名就是最好的答案**。

## 常见错误

### 在函数里用 `sizeof` 参数算元素个数
数组作为参数传进函数时已经退化成指针，函数里的 `sizeof arr` 是 8（指针大小），不是数组的字节数。下面的程序对任何长度的数组都会打印 2：

```c run id=err-param-sizeof expect=OK warnings=allow
#include <stdio.h>

static void report(int arr[5]) {
    /* 错：arr 已经是指针，sizeof arr 恒为 8 */
    printf("函数里 sizeof arr = %zu\n", sizeof arr);
}

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    report(a);
    printf("函数外 sizeof a = %zu\n", sizeof a);
    return 0;
}
```
```output
函数里 sizeof arr = 8
函数外 sizeof a = 20
```

正确做法：**把元素个数作为参数一起传进去**（`void f(int arr[], int n)`），或者用"指向整个数组的指针"（`void f(int (*pa)[5])`，但那只适用于长度固定的数组）。

### 用 `sizeof(a + 0)` 当整个数组的大小
`a + 0` 是一个**指针表达式**，虽然它的值等于 `a`，但类型已经是 `int *`，所以 `sizeof(a + 0)` 是 8 而不是 20。加一个 `0`、加一个 `i`、传给函数，都会触发退化：

```c run id=err-sizeof-expr expect=OK warnings=allow
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("sizeof(a + 0) = %zu\n", sizeof(a + 0));   /* 指针，不是数组 */
    printf("sizeof a = %zu\n", sizeof a);
    return 0;
}
```
```output
sizeof(a + 0) = 8
sizeof a = 20
```

### 把 `&a` 赋给 `int *`
`&a` 的类型是 `int (*)[5]`，不能赋给 `int *`。Clang 会直接报错（`incompatible pointer types`）。如果强行写成 `int *p = (int *)&a;`，编译器不再提醒，但 `p + 1` 只走 4 字节——你把"指向整个数组"的信息丢掉了。

```c run id=err-addr-type expect=CE
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int *p = &a;      /* error: incompatible pointer types */
    printf("%d\n", *p);
    return 0;
}
```

### 给数组名赋值
数组名不是可修改的左值，`a = b;`、`a++` 都不合法。数组之间也不能整体赋值（这一点和结构体不同）。要"复制数组"必须逐个元素复制，或者用 `memcpy`。

```c run id=err-assign expect=CE
#include <stdio.h>

int main(void) {
    int a[5] = {0};
    int b[5] = {0};
    a = b;            /* error: array type 'int[5]' is not assignable */
    return 0;
}
```

### `extern` 声明与定义的类型不匹配
在另一个文件里写 `extern int a[];`（不完整类型）而定义是 `int a[5];` 是合法的；但如果写成 `extern int *a;`，编译器会以为 `a` 是一个**指针变量**，而链接时找到的却是数组——程序会在运行时把数组的前 8 个字节当成指针解引用，行为完全错误，而且通常没有任何编译警告。**数组定义配数组声明，指针定义配指针声明**，不要混用。

## 客观题

### q-s2-array-vs-pointer-1 single
设有 `int a[5];`，`int *p = a;`。下面哪一句是**正确**的？（64 位环境，`int` 占 4 字节）

- [x] `&a + 1` 与 `&a` 的数值相差 20，类型是 `int (*)[5]`。
  > 对。`&a` 取的是"整个数组"的地址，类型为"指向 `int[5]` 的指针"，所以 `+1` 跳过整个数组 5 × 4 = 20 字节。
- [ ] `&a` 的类型是 `int *`，`&a + 1` 前进 4 字节。
  > 错。`&a[0]` 才是 `int *`；`&a` 作用于数组对象本身，类型是 `int (*)[5]`，步长是整个数组。
- [ ] `sizeof(a + 0)` 等于 `sizeof(a)`，都是 20。
  > 错。`a + 0` 已经退化成 `int *`，`sizeof(a + 0)` 是指针大小 8；只有 `sizeof a`（操作数是数组类型）才是 20。
- [ ] 可以写 `a = p;` 让数组名指向别处。
  > 错。数组名不是可修改的左值，`a = p` 是编译错误；数组的地址在它的生命周期内固定不变。
