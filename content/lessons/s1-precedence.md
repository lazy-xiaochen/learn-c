## 讲解

### 优先级与结合性
一个表达式里有多个运算符时：
- **优先级**决定谁先算：`a + b * c` 先算乘法；
- **结合性**决定同级运算符的顺序：`a - b - c` 是 `(a - b) - c`（左结合），`a = b = c` 是 `a = (b = c)`（右结合）。

常用运算符从高到低（同一行优先级相同）：

| 优先级 | 运算符 | 结合性 |
|---|---|---|
| 1 | `()` `[]` `->` `.` 后置`++` `--` | 左 → 右 |
| 2 | 前置`++` `--` 一元`+` `-` `!` `~` `*`(解引用) `&`(取地址) `sizeof` `(类型)` | **右 → 左** |
| 3 | `*` `/` `%` | 左 → 右 |
| 4 | `+` `-` | 左 → 右 |
| 5 | `<<` `>>` | 左 → 右 |
| 6 | `<` `<=` `>` `>=` | 左 → 右 |
| 7 | `==` `!=` | 左 → 右 |
| 8 | `&` | 左 → 右 |
| 9 | `^` | 左 → 右 |
| 10 | `\|` | 左 → 右 |
| 11 | `&&` | 左 → 右 |
| 12 | `\|\|` | 左 → 右 |
| 13 | `?:` | **右 → 左** |
| 14 | `=` `+=` `-=` 等赋值 | **右 → 左** |
| 15 | `,` | 左 → 右 |

不需要死记整张表，记住几个"反直觉"的地方就够了：**位运算 `& ^ |` 比比较 `== <` 还低；移位比加减低；赋值几乎最低**。拿不准时就加括号。

### 陷阱 1：a & b == c
直觉上是"a 与 b 的结果是否等于 c"，实际上 `==` 先算：`a & (b == c)`。

```c run id=and-eq warnings=allow
#include <stdio.h>

int main(void) {
    int a = 6, b = 3, c = 2;          /* 6 & 3 = 2，所以我们期望结果为真 */
    printf("%d\n", a & b == c);       /* 实际：a & (3 == 2) = 6 & 0 = 0 */
    printf("%d\n", (a & b) == c);     /* 加括号：(6 & 3) == 2 → 1 */
    return 0;
}
```
```output
0
1
```

判断奇偶时写 `if (x & 1 == 0)` 是同一个错误：它等价于 `x & 0`，永远为假。

### 陷阱 2：移位与加法
`x << 1 + 1` 中 `+` 优先级更高，实际是 `x << 2`：

```c run id=shift-plus warnings=allow
#include <stdio.h>

int main(void) {
    unsigned int x = 3;
    printf("%u\n", x << 1 + 1);      /* 3 << 2 = 12 */
    printf("%u\n", (x << 1) + 1);    /* 6 + 1 = 7 */
    return 0;
}
```
```output
12
7
```

用移位拼数字时尤其要小心：`hi << 8 + lo` 实际是 `hi << (8 + lo)`。

### 陷阱 3：赋值放在条件里
`=` 的优先级比 `!=` 低：

```c run id=assign-cond warnings=allow
#include <stdio.h>

int main(void) {
    int c;
    if ((c = 65) != 0) printf("c = %d\n", c);  /* 先赋值，再比较：c = 65 */
    if (c = 65 != 0) printf("c = %d\n", c);    /* 先比较 65 != 0 得 1，再赋值：c = 1 */
    return 0;
}
```
```output
c = 65
c = 1
```

以后读文件时经常写 `while ((ch = getchar()) != EOF)`，里面那对括号**必不可少**。

### 陷阱 4：i = i++ 是未定义行为
优先级和结合性只决定"怎么分组"，**不决定"什么时候生效"**。C 标准规定：在两个"序列点"之间（大致可以理解为同一个完整表达式内），如果对同一个变量做了两次修改，或者一边修改一边读取（读取不是为了计算新值），行为就是**未定义的**。

```c run id=i-eq-i-pp warnings=allow
#include <stdio.h>

int main(void) {
    int i = 1;
    i = i++;          /* 对 i 修改了两次：一次是 ++，一次是赋值 */
    printf("%d\n", i);
    return 0;
}
```
```output
1
```

在本平台的编译器上它输出 1，但这**不是**"正确答案"：标准没有规定结果，换一个编译器、换一个版本或者换一个优化级别，都可能得到 2 或别的结果。注意编译时的警告 `multiple unsequenced modifications to 'i'`——编译器已经在提醒你了。

类似的写法还有：`j = j++ + ++j`、`a[n] = n++`、`printf("%d %d", k, k++)`、`f(i++, i++)`。它们的共同点是：**同一个变量在一个表达式里既被修改，又在别处被使用**。解决办法永远是拆成多条语句。

### 陷阱 5：条件运算符的范围
`?:` 的优先级很低，比 `+` 还低：

```c run id=ternary
#include <stdio.h>

int main(void) {
    int a = 5, b = 3;
    int m1 = a > b ? a : b + 100;      /* 是 a > b ? a : (b + 100)，结果 5 */
    int m2 = (a > b ? a : b) + 100;    /* 想"取较大值再加 100"必须加括号，结果 105 */
    printf("%d %d\n", m1, m2);
    return 0;
}
```
```output
5 105
```

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra prec.c -o prec
```

本节的所有陷阱，`-Wall` 都会给出警告：`& has lower precedence than ==`、`operator '<<' has lower precedence than '+'`、`multiple unsequenced modifications`、`using the result of an assignment as a condition`。**这正是要求始终打开 `-Wall -Wextra` 的原因。**

## 常见错误

### 用 (x & 1 == 0) 判断偶数
等价于 `x & 0`，永远为 0。写成 `(x & 1) == 0` 或 `x % 2 == 0`。

### 以为加了括号就能"控制"自增的时机
`i = (i++)` 和 `i = i++` 一样是未定义行为。括号改变的是分组，不会在中间插入序列点。

### 依赖函数参数的求值顺序
`f(a(), b())` 中先调用 a 还是先调用 b 是**未指定**的（编译器可以任选）。如果两个函数有相互依赖的副作用，先分别调用、存进变量，再传给 f。

## 客观题

### q-s1-precedence-1 single expr-reasoning
设 `int a = 12, b = 10, c = 8;`，表达式 `a & b == c` 和 `(a & b) == c` 的值分别是：
- [ ] 1 和 1
  > 第一个表达式里 `==` 先算：b == c 即 10 == 8 为 0，a & 0 = 0。
- [x] 0 和 1
  > 正确。`a & b == c` 是 `a & (b == c)` = 12 & 0 = 0；`(a & b) == c` 中 12 & 10 = 1100 & 1010 = 1000 = 8，8 == 8 为 1。
- [ ] 8 和 1
  > 8 是 a & b 的值，但第一个表达式根本没有先计算 a & b。
- [ ] 0 和 0
  > 加了括号后先算 12 & 10 = 8，再与 8 比较，结果为 1。

### q-s1-precedence-2 multiple ub-analysis
下列语句中，哪些包含**未定义行为**？（i 已初始化为 1，a 是长度为 10 的 int 数组）
- [x] `i = i++;`
  > 同一个表达式中对 i 有两次无序的修改（自增和赋值），是未定义行为。
- [ ] `i = i + 1;`
  > 只修改了一次 i，右边对 i 的读取是为了计算新值，这是完全合法的。
- [x] `a[i] = i++;`
  > 左边读取 i 来确定下标，右边修改 i，两者之间没有先后顺序，是未定义行为。
- [ ] `i++, i++;`
  > 逗号运算符的左右两边之间有序列点：先完成左边的 i++，再执行右边的 i++，行为是确定的（i 变成 3）。
- [x] `i = ++i + i++;`
  > 对 i 有三次无序的修改/读取，是未定义行为。
