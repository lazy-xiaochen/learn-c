## 讲解

### 程序是什么
计算机只能执行由 0 和 1 组成的**机器指令**，人很难直接写。于是我们用 C 语言这样的"人能读懂"的语言写出**源代码**（保存为 `.c` 文件），再交给一个叫**编译器**的程序，把它翻译成计算机能执行的**可执行文件**（Windows 上是 `.exe`）。

所以写 C 程序需要两样工具：

| 工具 | 作用 | 本平台里对应的位置 |
|---|---|---|
| 编辑器 | 写和修改源代码（纯文本） | 页面里的代码框 |
| 编译器 | 把源代码翻译成可执行文件 | 点"运行"时在后台自动调用 |

本平台内置了编译器（Clang，用法和 GCC 几乎相同），你不需要安装任何东西。

### 第一次运行
下面就是一个完整的 C 程序。点击代码框上方的**运行**按钮，平台会先编译、再执行，并在下方显示程序的输出。你可以随意修改引号里的文字再运行，看看输出有什么变化。

```c run id=hello
#include <stdio.h>

int main(void) {
    printf("你好，C 语言！\n");
    return 0;
}
```
```output
你好，C 语言！
```

现在不需要理解每一行的意思，下一节"第一个 C 程序的完整解剖"会逐行讲解。先记住三件事：
1. 程序从 `main` 开始执行；
2. `printf` 用来在屏幕上输出文字，`\n` 表示换行；
3. 每条语句以英文分号 `;` 结尾。

### 程序是一条一条往下执行的
计算机不会猜你的意思。`main` 里的语句从上往下一句一句执行，轮到哪一句就做哪一句，所以**输出的先后顺序完全由你写的顺序决定**：

```c run id=order
#include <stdio.h>

int main(void) {
    printf("第 1 步：打开文件\n");
    printf("第 2 步：读取内容\n");
    printf("第 3 步：关闭文件\n");
    return 0;
}
```
```output
第 1 步：打开文件
第 2 步：读取内容
第 3 步：关闭文件
```

初学者常以为 `printf` 只是"先把文字准备好，最后一起显示"，于是随意调换语句顺序。其实每条 `printf` 在轮到它的时候就立刻把内容送出去，把上面三行调换一下，输出就跟着调换。

还有一个相关的坑：`return 0;` 的意思是"程序到此结束"，写在它后面的语句永远不会执行。所以要在屏幕上看到的东西，必须放在 `return` 之前。

### 程序也可以读取输入
很多程序需要用户提供数据。下面的程序从**标准输入**（键盘）读入两个整数，输出它们的和。在平台里，你可以在代码框下方的"输入"框中填写数据，这里预先填好了 `3 5`：

```c run id=sum stdin="3 5"
#include <stdio.h>

int main(void) {
    int a, b;
    if (scanf("%d %d", &a, &b) != 2) {
        printf("输入格式不对\n");
        return 1;
    }
    printf("%d\n", a + b);
    return 0;
}
```
```output
8
```

试着把输入改成 `10 -4`，或者故意输入 `abc`，看看程序的反应。`scanf` 的用法会在"格式化输入"一节详细讲。

### 编译通过不等于结果正确
编译器只检查两件事：**语法对不对**（分号、括号有没有漏），**类型配不配**（该放整数的地方有没有放小数）。它不检查你的**思路**对不对。所以完全可能编译零警告、程序正常退出，结果却是错的：

```c run id=avg stdin="3 4"
#include <stdio.h>

int main(void) {
    int a, b;
    if (scanf("%d %d", &a, &b) != 2) return 1;
    printf("用整数算：%d\n", (a + b) / 2);       /* 7 / 2 得 3，小数部分被丢掉 */
    printf("用小数算：%.1f\n", (a + b) / 2.0);   /* 3.5 */
    return 0;
}
```
```output
用整数算：3
用小数算：3.5
```

同一个算式，只因为把 `2` 写成了 `2.0`，结果就从 3 变成 3.5。编译器一句提醒都不会给，因为在它看来"整数除以整数得到整数"完全合法。初学者最容易在这里吃亏：程序不报错、正常退出，就以为万事大吉，直到判题给出"答案错误"（WA）。

所以写完程序要**自己先算一遍预期结果**，再拿它和程序的输出对照。这一步不能省，它比"多盯着代码看几遍"有用得多。

### 三类错误，排查方向完全不同
| 出错阶段 | 典型报错 | 编译器能发现吗 | 先检查什么 |
|---|---|---|---|
| 编译（语法/类型） | `expected ';' after expression`、`unknown type name 'Int'` | 能，直接拒绝生成程序 | 报错里指出的**行号**，以及它的上一行有没有漏分号 |
| 链接（找不到实现） | `undefined reference to 'main'` | 能，但只在链接阶段才报 | 函数名拼写、需要的源文件有没有全部写进命令 |
| 运行（逻辑） | 没有任何报错，结果不对 | **不能** | 自己手算的预期结果、程序的中间输出 |

### 判题是怎么回事
做题时，你写的程序会被平台用很多组**测试数据**运行：每组数据作为输入喂给程序，再把程序的输出和标准答案逐行比较。全部一致才算"通过"（AC）。所以：
- 输出必须**和题目要求完全一致**，不要多输出"请输入"、"结果是"之类的提示文字；
- 程序只能通过**标准输入**读数据，不会有人在键盘前帮你输入。

## 编译与运行

在平台里点"运行"即可。如果你在自己的电脑上安装了 GCC（Linux/macOS 自带或可用包管理器安装，Windows 可以安装 MinGW-w64），在**命令行**里这样编译和运行：

```bash
gcc -std=c17 -Wall -Wextra hello.c -o hello    # 编译：hello.c → 可执行文件 hello
./hello                                        # Linux / macOS 运行
hello.exe                                      # Windows 运行
```

各部分的含义：

| 片段 | 含义 |
|---|---|
| `gcc` | 调用编译器（换成 `clang` 效果相同） |
| `-std=c17` | 按 C17 标准编译（本平台统一使用 C17） |
| `-Wall -Wextra` | 打开常用警告。警告往往意味着 bug，**初学者务必开启** |
| `hello.c` | 源文件 |
| `-o hello` | 指定输出的可执行文件名；不写时默认叫 `a.out`（Windows 上是 `a.exe`） |

本平台编译时还会额外加上 `-fsanitize=address,undefined`，用来在运行时捕捉越界访问等错误，后面的章节会用到。

## 常见错误

### 用了中文标点
中文输入法下打出的 `；` `（` `）` `“ ”` 和英文的 `;` `(` `)` `" "` 看起来很像，但对编译器来说是完全不同的字符。这是初学者最常见的编译错误。下面的代码中 `printf` 这一行末尾用了中文分号：

```c run id=cn-semicolon expect=CE
#include <stdio.h>

int main(void) {
    printf("hi\n")；
    return 0;
}
```

编译器会报告"无法识别的字符"一类的错误。**写代码时请切换到英文输入法**，只有引号里面的文字可以是中文。

### 把 main 写错
`main` 拼写错误（例如写成 `mian`）时，每个函数本身都没问题，所以"编译"阶段能通过，但最后一步"链接"会失败，因为找不到程序的入口 `main`：

```c run id=mian expect=CE
#include <stdio.h>

int mian(void) {
    printf("hi\n");
    return 0;
}
```

看到 `undefined symbol: main`、`undefined reference to main` 或者 `WinMain` 之类的报错时，首先检查 `main` 的拼写。

### 输出了多余的提示文字
在自己电脑上写程序时，我们习惯输出"请输入两个数："这样的提示。但判题时程序的**全部输出**都会和标准答案比较，多出的提示文字会导致"答案错误"（WA）。做题时只输出题目要求的内容。

### 忘了写 \n，几行输出挤成一行
`printf` 不会自动换行，`\n` 才是"换到下一行"的指令。两个 `printf` 里只要有一个忘了写 `\n`，两次输出就会粘在一起：

```c run id=no-newline
#include <stdio.h>

int main(void) {
    printf("结果 %d", 12);       /* 没有 \n */
    printf("结果 %d\n", 3);
    printf("下一行\n");
    return 0;
}
```
```output
结果 12结果 3
下一行
```

这种错误在判题时特别隐蔽：数字全对，只是排版不同，但判题是逐行比较的，整行内容不一样照样判错。养成习惯——**每一行输出的末尾都写 `\n`**。

## 客观题

### q-s1-env-1 single
关于编辑器和编译器，下列说法正确的是：
- [ ] 编译器负责把可执行文件翻译成 C 源代码
  > 方向反了：编译器把**源代码**翻译成**可执行文件**（机器指令），而不是反过来。
- [x] 编辑器用来编写源代码，编译器把源代码翻译成计算机能执行的可执行文件
  > 正确。源代码是给人读写的文本，编译器负责翻译成机器能执行的指令。
- [ ] 只要源代码写好了，不经过编译也可以直接运行
  > C 是编译型语言，源代码必须先经过编译（和链接）生成可执行文件才能运行。平台的"运行"按钮也是先编译再执行。
- [ ] `-Wall -Wextra` 会让编译器忽略所有警告，使编译更快
  > 恰恰相反，这两个选项是**打开**更多警告。警告常常指出真正的 bug，初学者应当始终开启。
