## 讲解

### 三种"不能用的指针"，名字不一样，后果也不一样

| 名字 | 怎么产生的 | 里面存的是什么 | 典型后果 |
|---|---|---|---|
| **野指针**（wild pointer） | 声明了指针却没初始化；或指向的对象早已不存在且没有记录 | 上一次留在栈上的垃圾值，可能是任何地址 | 可能"碰巧能跑"，也可能随机崩溃、改坏别的变量 |
| **空指针**（null pointer） | 主动写成 `NULL`；或函数用 `NULL` 表示"没找到/失败" | 一个所有平台都约定为"不指向任何对象"的值（通常是 0） | 解引用通常立即崩溃——这反而是**好事**，错误暴露得早 |
| **悬垂指针**（dangling pointer） | 指针原来有效，但它指向的对象已经消失：局部变量随函数返回失效、`free` 之后内存被回收 | 一个**曾经有效**、现在已失效的地址 | 最危险：内存还没被覆盖时"看起来完全正常"，等被覆盖后错误出现在很远的地方 |

关键事实：**C 语言不记录"指针指向的对象还活着吗"**。没有任何运行时检查能告诉你一个非空指针是否有效，判断责任完全在程序员身上。这既是 C 快的原因，也是 C 程序崩溃的主要原因之一。

### 空指针：唯一可以安全判断的"坏指针"
`NULL` 是 `<stddef.h>` / `<stdio.h>` 等头文件里定义的**空指针常量**（通常是 `((void *)0)`）。它表示"明确地不指向任何对象"，而且可以安全地拿来比较：

```c run id=wd-null
#include <stdio.h>

/* 找到返回元素地址，找不到返回 NULL —— 用返回值表达“可能失败” */
static int *find(int *a, int n, int key) {
    for (int i = 0; i < n; i++) {
        if (a[i] == key) {
            return &a[i];
        }
    }
    return NULL;
}

int main(void) {
    int a[5] = {3, 1, 4, 1, 5};
    int *p = find(a, 5, 4);
    if (p != NULL) {
        printf("找到 4，下标 %ld\n", (long)(p - a));
    }
    p = find(a, 5, 7);
    if (p == NULL) {
        printf("没找到 7：指针为空，跳过解引用\n");
    }
    return 0;
}
```
```output
找到 4，下标 2
没找到 7：指针为空，跳过解引用
```

为什么空指针反而"安全"？因为现代操作系统都把 0 号地址所在的页设为不可访问，解引用 `NULL` 会立刻触发段错误，程序当场停下。**错误暴露得越早越好**——这正是"函数失败就返回 `NULL`、调用者必须先判空"这个约定流行的原因。

### 野指针：没初始化的指针里到底是什么
局部变量（包括指针）不会自动初始化，里面是**上一次这块栈内存留下的内容**。所以：

```c run id=wd-init
#include <stdio.h>

int *g_ptr;          /* 全局变量：静态存储期，默认初始化为空指针 */

int main(void) {
    int *local = NULL;   /* 局部变量不会自动清零，必须自己写 */
    printf("全局指针默认为空？%s\n", g_ptr == NULL ? "是" : "不是");
    printf("局部指针已手动置空？%s\n", local == NULL ? "是" : "不是");
    return 0;
}
```
```output
全局指针默认为空？是
局部指针已手动置空？是
```

如果把 `int *local = NULL;` 写成 `int *local;`，它里面就是垃圾值。此时哪怕只是**读它的值**（比如 `printf("%p", (void *)local)`）在标准上都是未定义行为；更别说解引用了。注意：`-Wall` 会给"使用了未初始化的变量"警告，但只在编译器能追踪到的情况下——指针经过函数参数、数组、类型转换之后，编译器就看不见了，而错误依然存在。

**防御习惯：声明指针时就初始化**。暂时没有目标就写 `= NULL`，这比"以后再说"安全一万倍。

### 悬垂指针：对象没了，指针还在
这是三种里最隐蔽的一种。看这段代码：

```c
int *make(void) {
    int x = 7;
    return &x;      /* 错：x 是局部变量，函数一返回就失效 */
}
```

函数返回时，它的**栈帧被弹出**，`x` 所在的那块内存立刻"不属于你"了。调用者拿到的指针指向一块已经失效的栈内存——这就是悬垂指针。它可能仍然读得出 7，因为还没人覆盖那块内存；但下一次函数调用就会把它覆盖成别的东西。

对比一下"对象一直活着"的版本：把 `x` 改成 `static`，它的存储期变成整个程序，指针就一直有效：

```c run id=wd-lifetime
#include <stdio.h>

static int counter = 0;      /* 静态存储期：程序结束时才失效 */

static int *next_counter(void) {
    counter++;
    return &counter;         /* 安全：counter 不会随函数返回消失 */
}

int main(void) {
    int *p = next_counter();
    *p += 10;
    int *q = next_counter();
    printf("p 和 q 指向同一个对象？%s\n", p == q ? "是" : "不是");
    printf("*q = %d\n", *q);
    return 0;
}
```
```output
p 和 q 指向同一个对象？是
*q = 12
```

`p` 与 `q` 相等、`*q` 是 12，说明它们指向的是同一个**一直存在**的对象。这正是"指针有效性 = 被指向对象的生命周期"的直观体现：指针本身只是一个数字，能不能用取决于它指的那个对象是否还活着。

### 内存里发生了什么

```memory title="函数 make 返回 &x 之后（地址是示意值，x 所在的栈帧已失效）"
地址        | 内容        | 变量   | 说明
0x7ffd1000  | 7           | x      | make 的局部变量，函数返回后这块栈内存失效
0x7ffd0ff8  | 0x401234    | 返回地址 | make 返回时已经用掉
0x7ffd2000  | 0x7ffd1000  | p      | 仍保存着失效地址：悬垂指针
0x601000    | 0           | g_ptr  | 全局指针，默认是空指针
```

`p` 里的数字 `0x7ffd1000` 本身没变，但 `0x7ffd1000` 这块内存已经"还给"了栈——下一次任何函数调用都可能往里写新内容。这就是为什么悬垂指针的错误往往**延迟出现**：写坏的是别人的变量，崩溃发生在完全无关的地方。

### 悬垂指针的两个常见来源
1. **返回局部变量的地址**（上面的 `make`）。编译器通常会给 `-Wreturn-stack-address` 警告，一定要当错误处理。
2. **`free` 之后继续用**。`free(p)` 只是把内存还给分配器，`p` 里仍然保存着那个地址，此时 `p` 就是悬垂指针。标准做法是 `free(p); p = NULL;`——把悬垂指针立刻变成"可以安全判断的空指针"，之后的误用会以空指针崩溃的形式暴露，而不是静默破坏数据。

第 5 阶段会系统讲 `malloc/free`，这里先记住结论：**释放内存不会清空指针，指针的失效与否必须由你手动管理**。

### 防御清单
- 声明指针就初始化：`int *p = NULL;` 或直接指向真实对象。
- 使用前判空；函数用 `NULL` 表示失败时，调用者必须检查返回值。
- 绝不返回局部变量的地址；需要返回就用 `static`、全局、调用者传入的缓冲区，或（第 5 阶段）堆内存。
- `free` 之后立刻 `p = NULL;`。
- 指针指向的数组/对象一旦销毁，所有指向它的指针都要当作失效，不要再保存"备用"。
- 打开 `-Wall -Wextra` 和 `-fsanitize=address,undefined`：ASan 能把"用了已返回函数的局部变量""释放后继续使用"直接抓出来并指出行号。

## 编译与运行

```bash
gcc -std=c17 -Wall -Wextra -g -fsanitize=address,undefined dangling.c -o dangling
./dangling
```

本平台用 Clang，命令等价：`clang -std=c17 -Wall -Wextra -g -fsanitize=address,undefined dangling.c -o dangling`。

说明：

- **`-Wall -Wextra`**：`-Wreturn-stack-address`、`-Wuninitialized` 这类"指针用错"的警告都在这里，看到就不要忽略。
- **`-fsanitize=address`（ASan）**：在每次内存访问时检查地址是否有效，能抓"释放后使用""栈越界""使用已返回函数的局部变量"，并打印调用栈和行号。
- **`-fsanitize=undefined`（UBSan）**：抓空指针解引用、有符号溢出、非法移位等。
- **`-g`**：保留调试信息，sanitizer 的报告才有文件名和行号。
- 注意 ASan 不能抓住**野指针**（未初始化指针）——它不知道那个垃圾值从哪来。这正是野指针最难查的原因，也说明"声明即初始化"必须成为肌肉记忆。

## 常见错误

### 解引用空指针
`*p` 里 `p` 是 `NULL` 时，程序立刻崩溃（也可能被 UBSan 报成"空指针解引用"）。这不是"读到 0"，而是未定义行为。

```c run id=err-null expect=UB
#include <stdio.h>

int main(void) {
    int *p = NULL;
    if (p == NULL) {
        printf("先检查，不访问\n");
    }
    printf("%d\n", *p);    /* 未定义行为：通过空指针读数据 */
    return 0;
}
```

### 返回局部变量的地址
函数返回后栈帧失效，指针悬垂。ASan 会报"使用了已返回函数的局部变量"，普通编译下则可能"看起来正常"，直到某次调用把栈覆盖。

```c run id=err-return expect=RE
#include <stdio.h>

static int *make(void) {
    int x = 7;
    return &x;      /* 编译器会警告：address of stack memory returned */
}

int main(void) {
    int *p = make();
    printf("%d\n", *p);   /* 读已经失效的栈内存 */
    return 0;
}
```

正确做法：让对象的生命周期覆盖指针的使用期——返回 `static` 变量的地址、让调用者传入缓冲区，或者（第 5 阶段）分配堆内存。

### `free` 之后继续使用
`free(p)` 之后 `p` 仍然保存着原地址，这块内存随时可能被下一次 `malloc` 分配给别人。此时读写 `*p` 是"释放后使用"（use-after-free），属于未定义行为。

```c run id=err-uaf expect=RE
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *p = malloc(sizeof *p);
    *p = 5;
    free(p);
    printf("%d\n", *p);    /* 悬垂指针：p 没有置空，内存已经还给分配器 */
    return 0;
}
```

标准做法是 `free(p); p = NULL;`，并在释放前确保没有别的指针还指向这块内存。

### 以为"野指针只要不崩溃就没问题"
`int *p; *p = 42;` 可能安静地改掉某个毫不相干的变量，程序在几百行之后才出错。更糟的是，这类错误在不同编译器、不同优化级别下表现完全不同——今天"能跑"不代表明天能跑。野指针没有"安全的用法"，唯一正确的处理是**声明时就初始化**。

## 客观题

### q-s2-wild-dangling-1 single
下面哪种情况产生的是**悬垂指针**？

- [ ] `int *p;` 声明之后没有初始化就使用。
  > 错。这是**野指针**：指针里是未初始化的垃圾值，从未指向过有效对象。
- [x] 函数返回局部变量的地址，调用者把这个地址保存下来继续使用。
  > 对。指针曾经指向一个有效对象（那个局部变量），函数返回后对象消失、指针仍保存着旧地址，这正是**悬垂指针**。
- [ ] `int *p = NULL;` 之后没有判空就解引用。
  > 错。这是**空指针**解引用：指针明确地不指向任何对象，不是"指向了已失效的对象"。
- [ ] `int a[3]; int *p = a + 3;` 之后只比较 `p` 与 `a + 3`，不解引用。
  > 错。`a + 3` 是数组末尾的下一个位置，标准允许**构造和比较**这个指针（只是不能解引用），它不是悬垂指针。
